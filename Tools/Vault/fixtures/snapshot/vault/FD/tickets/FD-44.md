## Goal
TDD §16: adopt the Zenithmon module codec shape verbatim (`Games/Zenithmon/Source/Core/ZM_SaveSchema.{h,cpp}`, `Games/Zenithmon/Docs/SaveFormat.md`): engine `Zenith_SaveData` owns the envelope; the payload is `FDSV` = header + length-framed modules `{moduleId, moduleVersion, byteLength, payload}`, one per sim system (world-deltas, belts, machines, power, research, presentation-prefs for M1; ids reserved for fluids, rail, drones, circuits, threat, blueprints/undo). Readers land exactly on `byteLength`; every read bounds-checks before allocating; writes stage + validate into a private stream before `Zenith_SaveData::Save`; reads parse into a temporary and publish only on complete success. Chunk deltas over procedural regen. Binding rule: every schema change ships its version bump + a compiled-blob migration test in the same commit. `Zenith_SaveData::Initialise("Foundry")` at boot with the between-tests clear hook.

## Definition of Done
- [ ] Save → load of a 2,000-tick M1 factory yields an identical world digest, then identical digests for a further 2,000 ticks on both instances
- [ ] The v1 compatibility golden blob is committed as a literal and loads; a truncated module and an oversized `byteLength` are both rejected without mutating the live sim
- [ ] A save of a world with 4,000 built chunks stores only deltas (size asserted below a bound proportional to built structures, not chunks)
- [ ] `Docs/SaveFormat.md` documents every module id, version and field order
- [ ] Foundry pinned baseline bumped from an OBSERVED Null run
