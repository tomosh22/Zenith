## Goal
TDD §5. `FD_World` owns `Zenith_HashMap<u_int64 /*packed s32,s32*/, FD_Chunk*>` for point lookup plus a **sorted-by-key chunk list** rebuilt on chunk create for every deterministic whole-world scan (hashmap iteration is slot-order and capacity-history dependent — `Zenith/Collections/CLAUDE.md`). `FD_Chunk` layers allocated lazily: terrain (1 KB tile bytes: ground type, resource id — always present), occupancy (`u_int32` handle per tile, 4 KB, on first construction), threat (pollution `u_int32`, nest list, pathing cost byte). Entity handles are `archetype(6) | generation(6) | slot(20)`, handle 0 is null. Multi-tile buildings write their handle into every covered tile from the archetype footprint. Terrain generation itself is M1; here the generator is a stub that fills a recognizable pattern from the seed.

## Definition of Done
- [ ] Units cover chunk create/lookup, sorted-list order after out-of-order creation, lazy occupancy allocation, and footprint writes/clears for a 3×3 building
- [ ] Handle pack/unpack round-trips every field at its extreme values and rejects a handle whose generation is stale
- [ ] A whole-world scan over the sorted list visits chunks in the same order regardless of creation order (digest-pinned)
- [ ] Memory: a world with 4,000 built chunks allocates occupancy only for those chunks (asserted via the allocation counter)
- [ ] Foundry pinned baseline bumped from an OBSERVED Null run
