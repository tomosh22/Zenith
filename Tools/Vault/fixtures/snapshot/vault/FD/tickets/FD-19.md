## Goal
TDD §6: "Splitters/sideloads are nodes in the line graph with explicit, serialized round-robin state (deterministic fairness). Circular runs are detected at merge time and assigned a deterministic anchor tile (no head)." GDD §5.2: splitters split/merge strict round-robin with input/output priority and a single per-side item filter as researched upgrades; undergrounds jump 4/6/8 tiles by tier; sideloading is lane-precise. Implement `FD_Splitter` nodes with serialized `uNextOutput`/`uNextInput`, priority and filter fields (default off; research toggles them in M1), sideload transfer onto the near lane, underground pairing on placement with tier-specific max span, and circular-run detection assigning the anchor at the lowest packed tile key.

## Definition of Done
- [ ] A 2-in/2-out splitter fed unequal inputs distributes exactly round-robin over 1,000 items (counts differ by at most 1)
- [ ] Output priority sends every item to the priority side while it has room; filter routes only the filtered item to its side
- [ ] Sideload onto a belt lands on the correct lane for all four approach directions
- [ ] An underground pair beyond its tier span is refused at placement with a reason code; within span, items traverse with correct timing
- [ ] A circular loop of belts carries items around indefinitely with conservation and a pinned digest; Foundry pinned baseline bumped from an OBSERVED Null run
