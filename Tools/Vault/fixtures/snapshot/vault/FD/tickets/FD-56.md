## Goal
TDD §19 #2: `Zenith_UICanvas::UpdateSize` computes `m_fScaleFactor` from the reference resolution and nothing reads it (`Zenith/UI/Zenith_UICanvas.cpp`), so desktop-authored panels are physically tiny on phone panels. Apply the scale factor in `RecalculateScreenBounds`, hit-testing and font sizing, **opt-in per canvas** so shipped games are undisturbed, aligned with the density-scaled touch-target floor (`ResolveTouchTargetRect`, 57 logical px). Acceptance from the register: one authored layout is tap-correct on a 1080×2400 phone and a 1080p desktop window. Engine units under `Zenith/UI/` for the opt-in path and for the untouched default path (existing UI unit output byte-identical).

## Definition of Done
- [ ] With scaling opted in, a 100 px authored button occupies `100 × scale` screen px and its hit rect matches (units at scale 1.0, 2.0, 2.75)
- [ ] With scaling off (default), every existing UI unit passes unchanged
- [ ] Font size honours the scale on the opted-in canvas
- [ ] Every affected game's pinned baseline (Combat, Zenithmon, RenderTest, Foundry) bumped from an OBSERVED Null run if the engine suite grew
