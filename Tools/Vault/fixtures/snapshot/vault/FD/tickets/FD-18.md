## Goal
TDD §6 "the load-bearing deep dive". Contiguous straight-through belt tiles merge into **transport lines** (two per belt run, one per lane), capped at **128 tiles**. A line stores `u_int32 m_uHeadGap` (1/256-tile), an `FD_Ring` of `{u_int8 uItem, u_int8 uFlags, u_int16 uGapToPrev}` (4 bytes per item), `{speed, length, state, wake links}`. Tick semantics: an unblocked line advances by decrementing `m_uHeadGap` by its per-tick speed (16/32/48) — one integer op; when the head reaches the line end it transfers (next line / blocked); a **blocked line sleeps entirely** and is woken by its consumer. Placing/removing a belt splices lines (merge / split at the edit tile). Deterministic counters: `uHeadAdvances`, `uLinesWoken`, `uSplices` per tick, exposed for op-count pins (TDD §18). Presentation-side position derivation is M1; this ticket is pure SimCore. Belt tiers Mk1/Mk2/Mk3 from GDD §5.2.

## Definition of Done
- [ ] Items never vanish: a 10k-tick fuzz over random place/remove/insert asserts total item count conservation and no negative gaps
- [ ] A blocked 128-tile line performs zero head advances per tick until its consumer frees space (op-count pinned at exactly 0, then exactly 1 on wake)
- [ ] Splice at an interior tile produces two lines whose concatenated item sequence equals the original
- [ ] Line length never exceeds 128 tiles; a 300-tile run chains into 3 lines with correct hand-off
- [ ] Golden digest after a canned 2,000-tick script is pinned; Foundry pinned baseline bumped from an OBSERVED Null run
