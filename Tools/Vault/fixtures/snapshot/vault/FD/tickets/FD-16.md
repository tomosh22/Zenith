## Goal
TDD §3. "The command queue is the ONLY write path into SimCore": UI callbacks fire after `Scenes().Update` in the frame, so every mutation is an `FD_Command` (`PlaceBuilding{archetype, tile, rot}`, `RemoveBuilding{handle}`, `SetRecipe{handle, recipe}` … — start with the variants M0 needs, leave the enum open) appended to an `FD_Ring` that `FD_Sim::Tick()` drains **first**, in order. Every command carries its inverse (the undo stack in M1 rides this). Implement the fixed phase order of TDD §3 as named empty phase functions (drain → timer wheel → electric → belts → splitters → inserters → fluids → trains → drones → circuits → threat → swap/advance RNG/`++m_uTick`) so later tickets fill slots without reordering. `FD_GameComponent::OnUpdate` gets the accumulator verbatim from TDD §3: `ClampDt`, at most `uMAX_TICKS_PER_FRAME = 3` ticks per frame, leftover debt discarded with a log line, pause = don't call `Tick`. A `(tick, command)` replay log plus the world seed reproduces a run bit-for-bit — the digest harness's spine.

## Definition of Done
- [ ] A unit feeds a 500-tick command script, replays the recorded log into a fresh `FD_Sim`, and both final digests are equal
- [ ] A unit proves commands enqueued mid-frame are applied at the next `Tick`, never between ticks
- [ ] Accumulator units: a 200 ms frame runs exactly 3 ticks and logs the discarded debt; a 16.6 ms frame runs 0 or 1 ticks; pause runs none
- [ ] `FD_Boot_Test` pins `Zenith_InputSimulator::SetFixedDt(1.f/30.f)` and asserts frame count == tick count over 90 frames
