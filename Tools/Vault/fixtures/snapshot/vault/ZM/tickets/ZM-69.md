## Goal

`Roadmap.md` S8, Gym 1 — **slice G1-2: author `Gym1.zscen` and the Thornacre door.**
Build the gym interior from the frozen constants G1-1 landed, place Fenna in it,
and connect it to Thornacre in both directions.

**SPLIT OUT of ZM-28 on 2026-08-25**, alongside G1-1 (the pure data and placement
header) and G1-3 (the badge and teach-move reward on a leader win). This is the
scene slice: it is the only one of the three that writes a tracked asset.

## ★ Two scene facts that decide how this slice is run

**`Gym1.zscen` does NOT exist, so this CREATES it.** The `.zscen` publish guard
(`Zenith_Editor.cpp`, inside `if constexpr (Zenith_IsNullRenderer())`) refuses a
headless boot CHANGING a committed scene, never creating one — its own comment
records that windowed boots author everything and publish unconditionally. So the
gym itself is reachable from a headless boot.

**But the Thornacre door is a CHANGE to a committed scene.** `Thornacre.zscen`
already exists and ships, and a warp into the gym has to be authored INTO it —
which the guard refuses headless. **That is why this ticket carries `needs-gpu`:**
build `Vulkan_vs2022_Debug_Win64_True` and drive the boot with a short automated
test carrying `--skip-unit-tests`. A GPU is assumed available; the label selects
the build, it does not gate the claim.

★ **A WINDOWED `_True` BOOT AUTHORS BEFORE IT TESTS.** Check `git status` after
every one, and expect exactly the scene paths this ticket means to touch. Two
consecutive boots must produce byte-identical output before the bytes are
committed — reproducibility is a separate property from correctness, and only the
second pair proves the first.

## What G1-1 has already frozen — read it, do not re-derive it

`Source/World/ZM_Gym1Placement.h` carries the hedge-maze walls, the leader's
station, the entrance and the arrival point as named constants, and a headless
unit already proves the declared maze is solvable. **Author from those constants.**
If the authored scene needs a value the header does not have, add it to the header
rather than spelling a literal in the authoring code — that is what made the R1
anchors auditable.

Fenna is `ZM_HUMAN_LEADER_FENNA`, an authored row that already has an appearance,
and her trainer row landed in G1-1.

- [ ] Two consecutive windowed boots produce byte-identical output for every

- [ ] `git status` after authoring shows exactly the intended scene paths and
      nothing else
- [ ] Every affected game's pinned baseline bumped from an OBSERVED run
