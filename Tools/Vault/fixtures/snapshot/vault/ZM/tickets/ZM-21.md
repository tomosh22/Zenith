## Goal

Status.md R1 slice table, R1-3: all four seam triggers land together, with a round-trip proof. Splitting them would leave a one-way seam nobody notices.

## Definition of Done

- [ ] All four gates authored in ONE commit
- [ ] A round-trip walk proves each seam in both directions
- [ ] Every affected game's pinned baseline bumped from an OBSERVED run

> **This is human-executed, by engine law rather than preference.** A headless
> run may CREATE a scene but never CHANGE one (the `.zscen` publish guard), so
> handing re-authoring to the loop would either no-op or violate the guard. It
> needs a windowed `Vulkan_*_True` boot carrying `--skip-unit-tests`.

> **Pinned counts.** A change that adds or removes a unit test reds the gate with
> ZERO failing tests: it asserts `ran == baseline` EXACTLY. Every affected game's
> pin must be bumped from an OBSERVED `Null_` run, never by arithmetic on the
> previous number — that is how a suite which also LOST a test still ratchets
> green. The orchestrator makes that edit, because only it has run the gate. This
> ticket names no site and no number on purpose: both have moved once already, and
> a stale one here is inlined into the worker prompt verbatim.

*Findings:*

5. **The slice's own spec was insufficient, and the worker said so.** Blocker #2's stated fix — "needle the WHOLE serialized payload per gate, ==1 each" — does not detect the swap it was written for: swapping Route 1's two gates leaves the file containing each payload exactly once. The implementation adds an ordering claim (`southName < southPayload < northName < northPayload`), sound because a `.zscen` entity record is `[fileIndex][name][parentFileIndex]` followed by that entity's components, written one entity at a time in authoring order. Two anti-vacuity clauses guard it: every needle must have BUILT, and the two Route 1 payloads must DIFFER. **If blocker #2's wording is carried anywhere else, it is worth correcting.**
6. **`ZM_SeamRoundTrip_Test` is invisible on CI.** It needs the gitignored terrain bakes and `RequestSkip`s without them; a skip counts as a pass. The payload needle is a BOOT unit reading tracked files for exactly this reason, but the *live* proof only ever runs on a machine with warm bakes.
7. **The gate run went RED once and GREEN once on the identical tree.** The first `-Phase verify` died at `<batch:exit=-2147483645>` (`0x80000003`, `EXCEPTION_BREAKPOINT`) after 9 of 68 tests; a re-run of the identical command returned 68 passed / 0 failed. Archaeology in `gates.log` shows the PRE-change tree also produced one red, with a different exit (`-1`) and a different abort point (`ZM_TrainerSightWalkUp_Test` vs `ZM_DialogueTalk_Test`), with two clean runs between. **This suite carries an intermittent hard abort whose crash point and exit code both drift.** No `Assertion failed:` line reaches either sink, because `Zenith_DebugBreak()` kills the process with the log buffer unflushed — so the diagnostic is destroyed by the failure that needs it. Filed as a workflow shortfall; it is not attributable to this ticket, and `ZM_DialogueTalk_Test` passes both in isolation and immediately after `ZM_SeamRoundTrip_Test`.
8. **A failed gate voids every gate behind it, silently.** When `zenith test` (line 2 of 4) failed, `run_unit_gate.ps1` and `doc_lint.ps1` never ran — so the pin was momentarily unconfirmed and `doc_lint` had never seen the edited docs. `tick_gates.json`'s `steps` array simply ends; nothing records which lines were skipped.
