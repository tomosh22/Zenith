## Goal

ZM-D-168 visual audit, item 4, and the half of ZM-58 a machine can do.
`Games/Zenithmon/Docs/History.md` records the finding as **"Dawnmere reads as an
open field, not a town — no buildings; the Trade Post and Care Center are
dialogue only."** Items 1, 2 and 3 of that audit closed on pixels (ZM-D-169 /
ZM-D-170 / ZM-D-171). Item 4 is still open.

**The gap is PLACEMENT, not assets.** Measured on `master` 2026-08-26; every
line number below was opened and confirmed on that date:

- `Games/Zenithmon/Assets/Buildings/` carries all **30** baked bundles, each
  complete — `.zmesh`, `.zmodel`, `.zmtrl`, `_facade.ztxtr` — `CareCenter` and
  `TradePost` among them. S4 `ZM_BuildingGen`'s SC5 disk bake shipped.
- **Not one of the seven committed `.zscen` files references a single one of
  them.** The string `Buildings/` occurs **zero** times in `Dawnmere.zscen`, and
  zero times in the other six.

So the town has a shop clerk NPC (`Npc_TradePostClerk`, authored at
`Games/Zenithmon/Source/World/ZM_DawnmerePlacement.cpp:70`), a Care Center heal
flow (`Games/Zenithmon/Source/CareCenter/ZM_CareCenter.cpp`), and roster rows for
both buildings with real 10.0 x 8.0 footprints
(`Games/Zenithmon/Source/Data/ZM_BuildingData.cpp:49-50`) — and no building
standing anywhere in the scene.

**ZM-58 is BLOCKED by this ticket and stays open.** ZM-58 is the aesthetic
judgement — a person looking at the finished town and deciding whether it reads
as one. **This ticket is not that.** Everything specified below is buildable and
machine-verifiable; finishing it is what gives ZM-58 something to look at.

### Constraints that bound the work

**★ THE TERRAIN RECIPE IS FROZEN — place inside the sites it already reserves.**
`Games/Zenithmon/Source/World/ZM_TerrainAuthoring.cpp` reserves Dawnmere pads
`Plaza` (512, 512) r=60, `Home` (384, 496) r=36, `Lab` (640, 552) r=48 and
`RouteGate`, plus the `Plaza`, `PlazaLandmark` and `ReservedRivalHome` landmarks.
Editing ANY pad, path or landmark regenerates the WHOLE Dawnmere heightmap — the
recipe's hydraulic erosion pass is region-wide rather than pad-local, as ZM-D-173
found the expensive way — which re-measures every table in
`Games/Zenithmon/Source/World/ZM_DawnmerePlacement.h` and re-bakes the committed
navmesh. That is a different and much larger ticket.

**★ RE-AUTHORING `Dawnmere.zscen` STILL NEEDS A WINDOWED BOOT, FOR A REASON THAT
IS NOT THE OLD ONE.** ZEN-6 (`cbebea74`, 2026-08-26) removed the engine's `.zscen`
publish guard, so a headless boot may now CHANGE a committed scene. It deliberately
did not change Zenithmon: `Games/Zenithmon/Zenithmon.cpp:3848` still defers
Dawnmere's scene authoring on a Null backend by the game's own choice, logging
`sceneAuthoring=DEFERRED`. ZM-D-190's canonical order therefore still applies —
build both configs; authoring boot on `Vulkan_*_True` with `--skip-unit-tests`;
`git status` the WHOLE `Assets/` tree, because a Vulkan boot authors all five
scenes; a second boot proving byte-identity; only THEN the gate.

**★ `ZM_GreyboxVisual` HAS NO BUILDING POPULATION.** It serves three — BLOCKOUT,
HUMAN and PROP — and its BLOCKOUT branch is pinned to `1.0e-4f` by
`Games/Zenithmon/Tests/ZM_AutoTests_InteriorTint.cpp:102`, so that branch must not
move. ZM-67's PROP branch is the nearest precedent for how a placed building
should resolve a generated static model. Its serialization contract is that
nothing new is written — `WriteToDataStream` emits a single version `u_int` — so a
fourth population must not grow the per-component byte count.

## Definition of Done

- [ ] The Trade Post and the Care Center stand in `Dawnmere.zscen` as placed
      entities resolving the baked `Buildings/TradePost` and `Buildings/CareCenter`
      bundles, on measured ground, inside terrain sites the recipe already
      reserves — with the recipe itself unedited.
- [ ] Their placement coordinates live as compiled constants in
      `Games/Zenithmon/Source/World/ZM_DawnmerePlacement.h`, derived rather than
      re-spelled, in the same measured-table idiom the Home shell and the SC-D lab
      numbers use.
- [ ] A boot unit in `Games/Zenithmon/Tests/ZM_Tests_CommittedSceneBytes.cpp` reads
      the committed `Dawnmere.zscen` off disk and reds if either building is
      absent, so a later re-author cannot silently drop them.
- [ ] Two consecutive authoring boots produce byte-identical `Dawnmere.zscen`, and
      the other four committed scenes are left untouched.
- [ ] The committed-asset SHA256 row for `Dawnmere.zscen` in
      `Games/Zenithmon/Docs/Status.md` matches the re-authored bytes.
- [ ] Every affected game's pinned baseline bumped from an OBSERVED run.
