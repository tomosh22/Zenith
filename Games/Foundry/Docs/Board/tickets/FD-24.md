## Goal
TDD §20 calls the device render spike "the single riskiest assumption in the project": the in-tree instancing record is 2,520 instances (desktop) and Foundry needs ~20k sustained. Build `FD_RenderSpike_Test` (automated, `requiresGraphics`): a flat ground of tiled quads, 20,000 static building instances across ~12 placeholder meshes in `Flux_InstanceGroup`s (`Zenith/Flux/InstancedMeshes/Flux_InstanceGroup.h`), 5,000 moving item instances updated every frame, RGBA8 tint churn on 10% per frame, one sun cascade set, uncompressed textures. Measure extract / upload / cull / draw via the CPU+GPU profiler and dump per-frame timings to `Build/artifacts/foundry/spike/*.json`. Flip `Foundry.zproj` to `"android": true` and regen so the same test builds for AGDE (the on-device run is the sibling ticket). Add `--spike-instances N` to scale the harness.

## Definition of Done
- [ ] `FD_RenderSpike_Test` passes windowed in `Vulkan_vs2022_Debug_Win64_True` and records extract/upload/cull/draw ms per frame over 600 frames
- [ ] Instance budgets are asserted by the test (20k + 5k exactly, no group exceeds 131,072)
- [ ] `Foundry.zproj` carries `"android": true` and `Build\regen.ps1` produces `foundry_agde.sln`
- [ ] The desktop numbers are recorded in `Docs/Status.md` beside the §15 budget row (instance re-extract+upload ≤ 1.5 ms)
