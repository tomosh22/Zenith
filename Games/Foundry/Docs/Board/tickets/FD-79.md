## Goal
TDD §19 #1 — the only from-scratch subsystem. Keep `Zenith_AudioBus::EmitSound(name, position, loudness, radius)` as the game-facing API and build the backend behind it under `Zenith/Audio/`: decode (WAV + ogg/vorbis via a vendored decoder in `Middleware/`), a mixer with buses (SFX / ambient / music / UI) and ducking, distance attenuation from a listener (the main camera), voice cap with priority eviction, and platform output via WASAPI on Windows. AAudio on Android and the density-mix tuning are phase 2 (M6-04). The Null backend and any machine without an audio device get a silent output that still runs the mixer, so units run in CI. DP's existing `EmitSound` tests must still pass (the recording behaviour stays available under test).

## Definition of Done
- [ ] Mixer units: bus gains, ducking envelope, attenuation curve, voice-cap eviction by priority — all deterministic over a fake clock
- [ ] Decoder units for a WAV and an ogg fixture (checked-in, tiny)
- [ ] A windowed RenderTest run plays an audible test tone through WASAPI (noted in the work log); silent output on Null
- [ ] DevilsPlayground's audio units pass unchanged
- [ ] Every affected game's pinned baseline bumped from an OBSERVED Null run
