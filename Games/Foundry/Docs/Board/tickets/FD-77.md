## Goal
TDD §19 #7: `Zenith_SaveData::Save` is synchronous with ~2× payload peak memory (stream + header copy) and a blocking write (`Zenith/SaveData/Zenith_SaveData.cpp`). Add `SaveAsync(slot, version, ownedBuffer, onComplete)`: the caller hands an owned snapshot buffer; CRC + header + write run on a task-system thread; completion callback on the main thread; same envelope and slot semantics; concurrent saves to the same slot are serialized. The sync path is unchanged for every existing game.

## Definition of Done
- [ ] Engine units: an async save produces a byte-identical file to the sync save of the same buffer; two overlapping async saves to one slot complete in order; the callback runs on the main thread
- [ ] Peak memory during async save is one payload copy plus the header (asserted with the allocation counter)
- [ ] Every affected game's pinned baseline bumped from an OBSERVED Null run
