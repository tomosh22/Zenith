## Goal
TDD §19 #4 (M2 basics): present mode is FIFO, hard-asserted (`Zenith/Vulkan/Zenith_Vulkan_Swapchain.cpp`, `ChooseSwapPresentMode`); no frame limiter, no `setFrameRate`, no thermal/battery reads. Add a target-framerate setting on `Zenith_GraphicsOptions` (0 = uncapped, 30, 60) implemented as a paced present in the Vulkan backend (sleep-until-deadline before present, no busy-wait) plus the `ANativeWindow_setFrameRate` hint on Android; Null and D3D12 backends accept the option as a no-op. Acceptance: stable 33.3 / 16.7 ms cadence on a 120 Hz panel. Thermal headroom polling is the M5 half (register #4 later).

## Definition of Done
- [ ] `Zenith_GraphicsOptions::m_uTargetFrameRate` exists, is serialized with the other options, and defaults to 0 for every existing game
- [ ] A windowed RenderTest run at target 30 shows a frame-time histogram centred on 33.3 ms (captured in the work log)
- [ ] The Null backend builds and runs with the option set (headless unit)
- [ ] Every affected game's pinned baseline bumped from an OBSERVED Null run if the engine suite grew
