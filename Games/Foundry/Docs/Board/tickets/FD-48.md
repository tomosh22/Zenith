## Goal
GDD §5.12: undo/redo (50 steps) — every placement, deletion and configuration change reverses honestly (resources refunded / re-drawn from the Reserve); undo is a first-class HUD button; GDD §6.5: "Undo is the safety net, not confirmation dialogs." TDD §3: every command carries its inverse; the undo stack is 50 command groups. `FD_UndoStack` in SimCore (it is sim state, saved in the blueprints/undo module): a drag-run is one group; redo re-applies the original; a group whose inverse cannot apply (e.g. the tile is now occupied) is refused with a reason and left on the stack.

## Definition of Done
- [ ] Undo of a 12-belt drag-run removes all 12 in one gesture and refunds exactly their cost (conservation unit)
- [ ] Redo after undo reproduces the pre-undo world digest
- [ ] The stack is capped at 50 groups and the oldest is dropped
- [ ] An inverse that cannot apply is refused without partial application (transactional — digest unchanged)
- [ ] Foundry pinned baseline bumped from an OBSERVED Null run
