## Goal
TDD §14–§15: "factory size never reaches the renderer." `FD_Sim::PostTickExtract(FD_Presentation&, alpha)` publishes presentation-owned snapshot buffers at tick rate (positions/phases for visible movers); render frames interpolate between the last two extracts. Only entities inside the camera rect (+1-chunk margin, + a shadow-length pad toward the sun) have render instances at all; Presentation materializes/dematerializes per chunk on visibility enter/exit from pooled per-mesh instance budgets. **Slot ledger:** `RemoveInstance` swap-and-pops without reporting the moved id, so keep a per-group `slot → owner` array and patch the tail owner on each removal — never clear-and-respawn per frame. Hard caps by tier (Workshop ≤ ~8k buildings + ~10k items; Logistics ≤ ~15k; Map ≤ ~10k quads) enforced by representation switching before budgets inflate, because group capacity is grow-only. Implement Workshop tier for buildings here; belt items/arms are M1-11, other tiers M3a. Honour `FD-D-001` if the fallback renderer was chosen.

## Definition of Done
- [ ] A scripted camera sweep over a 200-chunk factory never exceeds the Workshop instance cap (asserted in an automated test on the Null backend via the ledger counts)
- [ ] The ledger is consistent after 10k random add/remove operations (owner of every live slot is correct — unit)
- [ ] Instances exist only for chunks intersecting the view rect + margin; chunks leaving the view release their slots within one frame
- [ ] Interpolation alpha is derived from the accumulator and never reads sim state directly (Presentation reads only snapshot buffers — enforced by the lint direction: SimCore has no Presentation include, Presentation has no `FD_Sim` mutable reach)
