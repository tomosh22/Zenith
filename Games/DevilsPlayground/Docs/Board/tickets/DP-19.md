## Goal
MvpRoadmap Post-MVP backlog #1: *"A bot that plays 1000+ randomised runs per night and reports aggregate stats (win rate, decision diversity, death-cause distribution, Aelfric reaction frequency, reagent-collection times). Detects regressions in fun-proxies overnight."* The pieces exist: `Test_PersonalityPlaythrough.cpp` (8 personalities, the same bot toolkit), `Tools/dp_seed_matrix_run.ps1` and `dp_seed_matrix_analyse.py` (the 10-seed matrix and `REPORT.md`), and the telemetry recorder (`Zenith/Telemetry`, `DPTelemetry.h`, v3 format).

Scale the matrix to an unattended run: N randomised seeds times 8 personalities on the Release_False build in batch, a report with the five aggregates plus the two ratified balance criteria as pass/fail, a per-run history so a regression shows as a delta against the previous night, and a scheduled entry point (a script a Task Scheduler job or a workflow can call; the workflow itself is a human task). Determinism per cell stays (seed plus personality reproduces a cell). DP gates: `zenith build DevilsPlayground --headless`, the D3D12 link proof and `zenith test DevilsPlayground --headless`; the DP suite has no pinned unit-count row, so no pin bump applies unless `Zenith/**` is touched. Conventions: `Games/DevilsPlayground/Docs` are binding (AgentBriefing, TestPlan §0 verification contract, test-first inside the session), `Config/*.json` carries every numeric value, no paid or external services, and `Tools/check_acceptance_drift.ps1` must stay within 20% per test.

## Definition of Done
- [ ] One command runs N seeds times 8 personalities unattended and writes a report with the five aggregates, the two criteria and the delta against the previous run
- [ ] A planted balance change shows as a delta in the report (recorded once)
- [ ] `Docs/Status.md` names the report as the balance authority and the schedule entry point
