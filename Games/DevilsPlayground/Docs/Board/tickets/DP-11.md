## Goal
MvpRoadmap §3.3 (MVP-3.3.1 to 3.3.4): the nine item tags (Iron, Wood, Brass Key, Skeleton Key and the five reagents) get real meshes through the `.glb` import path, replacing the tinted cubes in `DPItemBase_Behaviour`, and the held-item visual moves from *"a floating cube 1.6 m above the body"* (Shortfalls §6.3) to the rig's hand socket (`Test_AssetMesh_ItemHeldSocket`). KEEP the cube system as a debug-mode fallback per AssetManifest §15 (a command-line flag, not a compile switch). The item-tag to mesh map lives in `Config/` next to the reagent registry.

Tests: every tag resolves a mesh (asset test), the held socket test, the pickup chain and drop tests unchanged (`Test_P1Drop_*`, `Test_P1Switch_*`), and the fallback flag renders cubes. DP gates: `zenith build DevilsPlayground --headless`, the D3D12 link proof and `zenith test DevilsPlayground --headless`; the DP suite has no pinned unit-count row, so no pin bump applies unless `Zenith/**` is touched.
