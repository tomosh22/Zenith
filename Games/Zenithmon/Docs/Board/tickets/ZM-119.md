## Goal

ZM-D-121 (the Care Center yes/no choice) records a known gap: *"the 'panel stays shown while awaiting' behaviour above has no windowed assertion, so a regression to `bShown = IsActive()` would not be caught."* The rule matters because the advance that opens the wait leaves the box `IsActive() == false`; the SC2 predicate would then hide the panel and blank the text, leaving two buttons floating over the world (the ZM-D-112 bleed-through failure). Today the rule is an inline expression inside `ZM_UI_DialogueBox::Present` (`Source/UI/ZM_UI_DialogueBox.cpp`, `const bool bShown = IsActive() || bAwaitingChoice;`), which touches UI elements and so is not reachable from a headless unit.

Scope: factor that expression into a public, pure, const predicate on `ZM_UI_DialogueBox` (e.g. `IsPanelShown()`), have `Present` use it unchanged, and add headless units in `Tests/ZM_Tests_DialogueBox.cpp` over the model: shown while lines are active, shown while a choice is armed and awaited after the last line (the case the ruling names), hidden when idle and after a resolve/close. Anti-vacuity: the awaited-choice unit must fail if the predicate were `IsActive()` alone. No behaviour change.

## Definition of Done

- [ ] `ZM_UI_DialogueBox` exposes the panel-shown rule as a pure predicate that `Present` uses, with no behaviour change
- [ ] Headless units cover active, awaiting-choice, idle and resolved states, and the awaiting-choice unit would red on `bShown = IsActive()`
- [ ] Shortfalls §1.6's note about the missing assertion is closed
- [ ] Every affected game's pinned baseline bumped from an OBSERVED run
