## Goal
`Roadmap.md` S8: *"`ZM_AutoTests_Slice` mini-playthrough (CB_HumanSession-style flat Act script + PROBEs, ~4-6k frames, windowed)"*, and the S8 gate's first clause: *"mini-playthrough new-game -> Badge 1 green"*. One automated test, `ZM_Slice_Test`, that starts a NEW GAME and plays through to the Bloom Badge with real input edges: PlayerHome, Aster's lab and the starter choice (the `ZM_IntroBeat_Test` phases, 18 of them, reused not re-implemented), out through Dawnmere's north seam onto Route 1, a wild encounter in the tall grass won through the real HUD, both Route 1 trainers, the seam into Thornacre, the gym door, the hedge maze to Fenna, her defeat and the badge and TM in a reloaded save.

**Pattern:** `Games/CityBuilder`'s `CB_HumanSession` flat Act script with PROBE steps that assert state between acts, driven by the ONE walk driver `Tests/ZM_TestWalkDrive.{h,cpp}` (read its header: the driver is camera-relative and 8-way quantised, so long legs are pursuit curves; route legs through the drive-leg tables the placement headers declare rather than inventing waypoints). Battles use `zm_instant_battles` where presentation timing would otherwise dominate the frame budget. Give it an explicit `m_iMaxFrames` with margin; `TestPlan.md` §6 says the slice test may join the batch only if it fits, otherwise it is gate-only via `--filter`.

**Why `needs-gpu`:** the run is `m_bRequiresGraphics = true` because it crosses every committed scene against gitignored terrain bakes and reads the battle HUD, which the Null backend skips-as-passed (`TestPlan.md` §5.10 caveat). It authors nothing; run it with `--skip-unit-tests` only because the authoring-boot units it does not need would otherwise lengthen the boot.

**Depends on** every S8 content slice: R1-5/6/9/10 (ZM-23/24/25/26), G1-2a/b (ZM-73/69). It is the ticket the S8 go/no-go (ZM-30) waits on.
