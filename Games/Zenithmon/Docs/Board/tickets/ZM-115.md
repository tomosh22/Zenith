## Goal
Shortfalls §3: *"NOTHING MECHANICALLY DISTINGUISHES A PAD FROM A SHELF. `Flatten` is a rate (35%/dab, and a pad issues two dabs) while `SetHeight` assigns; a recipe that uses a pad to level gameplay-critical ground compiles, bakes, and is wrong by metres. The rule is documented at the `Zenith_TerrainBrushTool` enum and in the playbook, but it is a READING rule: no test scans recipes for it."* `MapLayoutPlaybook.md` §3.1 and §3.2 record both failure directions. With S9 adding about eleven recipes and S10 nine more (ZM-84 to ZM-103), a reading rule will be misread.

Scope: a headless unit in `Tests/ZM_Tests_TerrainAuthoring.cpp` that walks every recipe's step plan (the recipes are compiled data in `Source/World/ZM_TerrainAuthoring.cpp`) and asserts that every landmark or pad a placement header declares as STOOD-ON (a building site, an NPC station, a seam gate, a spawn) is covered by a `SetHeight` shelf, and that no `Flatten` dab is the only leveller under such a site; plus the inverse from §3.2, that no shelf is issued where a test expects natural relief. The stood-on set comes from the placement headers' own tables, not a hand-maintained list, so a new region joins the check by declaring its stations. Anti-vacuity: a hand-built recipe with a pad under a station reds.

## Definition of Done
- [ ] A unit scans every compiled recipe and reds when a stood-on site is levelled by a Flatten pad rather than a SetHeight shelf, deriving the stood-on set from the placement headers
- [ ] The anti-vacuity arm over a hand-built recipe reds; all three shipped recipes pass
- [ ] Shortfalls §3 and playbook §3.1 note that the rule is now checked
- [ ] Every affected game's pinned baseline bumped from an OBSERVED run
