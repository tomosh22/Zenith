## Goal
`TestPlan.md` §5.9: *"for each region wave, an automated test walks EVERY warp edge in `ZM_WorldSpec` (doors, route mouths, gates) and asserts arrival scene + spawn tag; one scripted battle per route validates its encounter table end-to-end."* Today the only traversal proofs are hand-written per seam (`ZM_SeamRoundTrip_Test`, `ZM_PlayerHomeRoundTrip_Test`, `ZM_LabRoundTrip_Test` in `Tests/ZM_AutoTests_WorldTraversal.cpp` and siblings), each spelling its own waypoints. Fourteen more towns and routes cannot be covered that way. Build the harness once, so each region wave registers ONE test that is a data row.

Scope:
- A pure planner, `ZM_TraversalPlan`, that reads the compiled `ZM_WorldSpec` (connections and spawn tags) and the placement headers' drive-leg tables, and emits for a given set of scenes the ordered list of legs: (arrive at tag, drive to gate entity, expect scene X and tag Y). It is headless-testable against the 8-row table today: every edge appears exactly once, every leg's start and end are on a declared drive leg, and an edge to an unregistered scene is refused at plan time (the ZM-D-196 black-screen hazard, caught before a boot).
- An automated-test template that executes a plan with the ONE walk driver (`Tests/ZM_TestWalkDrive.{h,cpp}`: camera-relative, 8-way quantised, so legs must be straight or split at the fixed points the playbook §3.4 describes) and PROBEs arrival scene, spawn tag, player position within tolerance and no `Zenith_Error`, with a per-leg frame cap so a wedge reports the leg, not a distance.
- One scripted battle per ROUTE: force an encounter through the synthetic-density seam (`Tests/ZM_Tests_RouteEncounterSeam.cpp`) or a rigged RNG, and win it through the real HUD with `zm_instant_battles`, asserting the species drawn is in that route's table.
- Registration is a table: `ZM_Traversal_Route1_Test` (Dawnmere, Route 1, Thornacre, Gym 1 once ZM-69 lands) is the first row and the proof the harness works on shipped content; each wave adds its row.

Budget (TestPlan §6): single-mechanic tests stay under 900 frames; a region traversal is allowed more but must declare `m_iMaxFrames` with margin and be reported in the slowest-10 at the gate.
