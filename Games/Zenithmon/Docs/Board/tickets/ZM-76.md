## Goal
Route trainers for Routes 2-8, the PURE half, in the exact shape R1-5 (ZM-23) establishes for Route 1: `ZM_TrainerData` rows (party, prize money, a per-trainer defeat flag, AI tier, challenge lines, `ZM_BADGE_NONE`/`ZM_ITEM_NONE` rewards), `ZM_NpcData` rows naming them, `ZM_HUMAN_ID` appearances that clear the distinctness invariant, and placement stations in each route's placement header with FROZEN ground columns and a sight-cone justification. The region waves (ZM-84 to ZM-87) author the entities; this ticket re-authors nothing.

Design inputs: GDD §8 wild bands set the trainer levels per route (a trainer ace sits at the top of the route's band); two to four trainers per route, more on the long Routes 5 and 8, none on the Route 7 egg circuit beyond one (GDD §2.2 "long safe grass"); trainer classes reuse the generic outfits (`ZM_HUMAN_OUTFIT_TRAVELER`, `WORKER`, `TRAIL`) and the generic human models ZM-D-223 bound to the shared StickFigure rig.

Rules carried from S8 that this ticket owns for seven routes at once:
- **Every trainer is flagged** (ZM-D-196 ruling 3): `ZM_STORY_FLAG_ID` is append-only, 4096 bits, so one flag per trainer costs nothing and needs no schema bump; `Tests/ZM_Tests_StoryFlags.cpp` is a second pinned site.
- **The per-id claim check** (`Npc_EveryRegisteredTrainerIsClaimedByExactlyOneNpcRow` after ZM-23) must stay per-id; never bump a count. An omitted trailing `m_eTrainer` initializer is the `ZM_TRAINER_RIVAL_VESPER == 0` trap.
- **Palette headroom:** ZM-68 re-scopes the distinctness invariant to rows that can share a frame, which is what makes ~20 new appearances possible; this ticket is BLOCKED by it. Report achieved separations from the shipped tables.
- **Stations** are placed relative to each route's drive legs (playbook §3.3, §3.6): inside sight range of the lane, outside every other trainer's re-arm radius, off every gate approach, spelled in the header with the clearance pinned by boot units the wave's oracle later freezes.
