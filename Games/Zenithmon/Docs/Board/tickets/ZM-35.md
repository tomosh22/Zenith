## Goal
`Roadmap.md` S9: *"Weather zones (WorldSpec-driven, feeds battle modifiers)"*. The battle engine already realises weather (`ZM_WEATHER` in `Source/Battle/ZM_BattleTypes.h`: RAIN, SUN, SAND, SNOW, box 3 of S2) and the arena has a biome per source scene (`Components/ZM_BattleTransition.cpp`, id-tagged `ls_axBiome`). What does not exist is a way for a SCENE to declare its weather so a wild or trainer battle on it starts under that weather.

Scope, PURE: a `ZM_WEATHER m_eWeather` column on `ZM_WorldSpec` (default NONE for every existing row, so no existing battle changes); `ZM_BattleTransition` reads the source scene's row and seeds the battle config's opening weather with a duration convention the GDD fixes (permanent field weather, like mainline overworld weather); routes that GDD §2.2 describes as weathered get their rows filled (Route 9 permanent fog is NOT a battle weather and stays NONE; Routes 11-12 SNOW; Route 3 SUN; Route 5 RAIN; Route 13-14 SAND), the S10 rows landing with ZM-37. Units: the column is total, a scene with weather starts the battle with that weather active and the engine's weather modifiers apply on turn 1 (damage multiplier through `ZM_DamageCalc`), and a scene with NONE is byte-identical in event stream to today.

Presentation (rain or snow particles, sky tint) is deliberately NOT in this ticket; the HUD's existing weather line is the visible surface. If a visual pass is wanted it is an ZM-18 item.

## Definition of Done
- [ ] `ZM_WorldSpec` carries a weather column, every existing row reads NONE, and the integrity units cover it
- [ ] A battle entered from a weathered scene starts under that weather and the turn-1 damage modifier applies, proven headless through `ZM_BattleTransition` and the engine
- [ ] A scene with NONE produces an event stream identical to before the change, pinned by a golden comparison
- [ ] Every affected game's pinned baseline bumped from an OBSERVED run
