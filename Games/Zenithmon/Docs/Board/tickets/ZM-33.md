## Goal
`Roadmap.md` S9: *"Field evolution / stones; TM items"*, which is really the **item USE path**, the production surface ZM-D-196 ruling 1 recorded as absent: *"there is no way to USE an item at all: `ZM_UI_Bag` rows are inert and the battle engine never includes `ZM_Bag`, so catching does not even consume a ball."* Nothing has changed that since; G1-3 (ZM-70) grants the Verdant Lash TM as a bag item with zero runtime consumers, and Route 1's ground items (ZM-27) go into a bag nothing reads.

Build the one path and route every item category through it, using the data that already exists in `Source/Data/ZM_ItemData.h` (`ZM_ITEM_CATEGORY_*`, `ZM_ITEM_EFFECT_*` with 34 kinds, `m_eTaughtMove`, `m_bConsumable`):
- **Out of battle, from the Bag screen:** select an item, pick a target party slot (`ZM_UI_Party` by-value idiom), apply. MEDICINE (heal HP/PP, cure status, revive), TM (`TEACH_MOVE`: learnset-legal check, four-slot replace prompt, consumed unless `m_bConsumable` is false), EVO stones (`EVOLVE` on `m_eEvolvesTo` via the existing `ZM_Evolve` mutation in `Source/Battle/ZM_ExpAndLevel`, which today evolves only on LEVEL through the terminal battle queue), FIELD (repel: a step counter on `ZM_GameStateManager`), KEY items refuse with a line.
- **In battle:** the Fight/Catch/Run menu (`ZM_BattleDirectorCore`, `ZM_UI_BattleHUD`) gains ITEM: `DoItemAction` already exists for balls, so pass a REAL bag and consume the ball on throw; MEDICINE and BATTLE boosters resolve through the same effect table.
- **A pure `ZM_ApplyItem(ZM_GameState&, ZM_ITEM_ID, target)`** is the seam every caller goes through, so units can drive every effect kind headless against a hand-built state, including the refusals (wrong target, full HP, not consumable, unknown effect).

No save-schema change is expected (bag and party are persisted already; a repel counter is session state unless the design says otherwise, and if it must persist it is a version bump with a canned-blob test per `SaveFormat.md`). No new ECS order.

## Definition of Done
- [ ] Every `ZM_ITEM_EFFECT_*` kind either applies through `ZM_ApplyItem` or is refused with a named reason, and a totality unit over the enum proves no kind falls through
- [ ] From the Bag screen a potion heals a chosen party member, a TM teaches a learnset-legal move with a replace prompt, and an evolution stone evolves an eligible species out of battle, each proven by a headless UI-state unit and one windowed flow test
- [ ] In battle a thrown ball is consumed from the real bag and a medicine item resolves through the same seam, proven by the battle-menu tests
- [ ] The Verdant Lash TM granted by G1-3 can actually be taught, closing the zero-consumer note in ZM-D-213
- [ ] No save-schema change, or a version bump with a canned-blob migration test in the same commit
- [ ] Every affected game's pinned baseline bumped from an OBSERVED run
