*Findings:*

4. **The roll-seam proof is a reimplementation, not a call into production** (reviewer). `StepWalk`
   mirrors `ZM_TallGrassSystem::OnUpdate`'s composition by hand — necessarily, since `OnUpdate`
   needs a live entity, scene, player and a disk-loaded density map. It reuses the real pure
   functions (`QuantizeToTile`, `IsTileTransition`, `IsGrassDensity`, `RollStepForScene`), so it
   catches regressions in those and in Route 1's data — but **not** in `OnUpdate`'s own control
   flow. Reorder the gates, or move the roll outside the density gate, and a live boot
   misbehaves while this whole file stays green. The file's own header discloses this ("NO
   `ZM_TallGrassSystem` instance is constructed"), but its adjacent claim to replicate the
   "EXACT composition" is true only as a snapshot of today's code. **Worth its own ticket** — a
   test-only injection seam letting a real instance run against a synthetic map. Not filed:
   whether that seam is worth building is a judgement, unlike ZM-66 which R1-4 requires.
5. **The worker considered and rejected a workaround, and was right to.** A runtime "on scene
   load, if ROUTE and terrain lacks the component, add it" hook inside `ZM_BattleTransition`'s
   persistent `OnUpdate` would have touched no scene bytes and would have passed every gate. It
   was rejected as a new architectural pattern invented unreviewed, landing in
   `OnAwake`-not-firing-on-runtime-`AddComponent` territory the DecisionLog has been burned by.
6. **The zero-trap in the id-tag, and why it is inert** (reviewer). `ZM_SCENE_FRONTEND` and
   `ZM_BATTLE_BIOME_MEADOW` are both enumerator 0, so a value-initialised row satisfies
   `m_eScene == index` for free **at index 0 only**. FRONTEND's documented real answer is also
   MEADOW, so the blind spot cannot hide a defect; every other index, ROUTE1 included, is
   genuinely protected. Pre-existing, not a regression.
7. **`uZM_DEFAULT_ROUTE_ENCOUNTER_RATE` is now unused** — Route 1 was its only consumer.
   Deliberately kept, reserved for the next ROUTE row, per the ruling. `TreatWarningsAsErrors`
   is on for win64 but MSVC has no diagnostic for an unused namespace-scope `constexpr`, and the
   green build confirms it. The AGDE/clang path is not in this gate list and is unexercised;
   `-Wunused-const-variable` is not in `-Wall` for C++, so the risk is low but unproven.
