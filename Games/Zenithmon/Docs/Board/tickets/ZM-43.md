## Goal
`Roadmap.md` S12: *"Per-chapter segment tests in the batch suite"*. `TestPlan.md` §5.11: *"`ZM_Segment_<Chapter>_Test`: per-chapter scripted playthroughs sized to stay inside the batch budget; together they cover the full critical path."* The region traversal tests (ZM-74 rows) prove every edge is walkable; the segment tests prove the GAME is playable chapter by chapter with real progression: badges earned, wardens passed, rival beaten, items used.

Chapters (one test each, from a canned save at the chapter's start so each fits the budget): Dawnmere-to-Bloom (the slice, ZM-29, re-registered as `ZM_Segment_1_Test`), Route 2-to-Kiln, Routes 3-4-to-Tide, Route 5-to-Coil, Routes 6-8-to-Gale, Route 9-to-Wisp, Routes 10-11-to-Rime, Routes 12-14-to-Crest, Highcrown-to-Champion (ZM-38's gauntlet becomes its last act). Each is a `CB_HumanSession`-style Act script with PROBEs, drives the ONE walk driver, uses `zm_instant_battles`, and ends by writing the canned save the next chapter starts from (`Docs/SaveFormat.md` canned-blob policy: the blobs are committed and versioned so a schema change reds every chapter that reads one, which is the point).

Budget (TestPlan §6): the headless batch must stay in single-digit minutes at end state; segment tests are `m_bRequiresGraphics = true` and run in the windowed gate set, each with an explicit `m_iMaxFrames`; the slowest-10 report at the S12 gate decides which are demoted to gate-only.

## Definition of Done
- [ ] Nine `ZM_Segment_*_Test` registrations exist, each starting from a committed canned save and ending at its badge or the Champion, passing windowed with recorded frame counts
- [ ] The canned saves are committed and every chapter reads its predecessor's, so the chain proves the schema end to end
- [ ] Frame caps declared; the slowest-10 report is recorded in `Docs/Status.md`
- [ ] Every affected game's pinned baseline bumped from an OBSERVED run
