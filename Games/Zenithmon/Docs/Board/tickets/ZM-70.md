## Goal

`Roadmap.md` S8, Gym 1 — **slice G1-3: beating Fenna awards the Bloom Badge and
grants Verdant Lash.** Wire the reward onto the leader-defeat path and prove both
halves survive a save round trip.

**SPLIT OUT of ZM-28 on 2026-08-25**, alongside G1-1 (the pure data and placement
header) and G1-2 (authoring the scene). This slice is **PURE** — it re-authors
nothing and needs no scene, so it can run in PARALLEL with G1-2 once G1-1 lands.

## Almost all of the machinery already exists

This is a wiring slice, not a systems slice, and the scope is easy to overestimate:

- **Badge state is complete and persisted.** `uZM_BADGE_COUNT = 8`,
  `m_uBadgeMask`, `AwardBadge(uIndex)`, `HasBadge`, `GetBadgeCount` live in
  `Source/Party/ZM_GameState.h:89-176`, and save module 5 already reads and writes
  the mask (`Source/Core/ZM_SaveSchema.cpp:21`, `:980`, `:1058`). **Add no badge
  state and change no save schema.**
- **Teach-move already exists as an item effect** — `ZM_ITEM_CATEGORY_TM` and
  `ZM_ITEM_EFFECT_TEACH_MOVE` with `m_eTaughtMove`
  (`Source/Data/ZM_ItemData.h:30`, `:67`, `:169`). **Add no new effect kind.**
- G1-1 landed the Bloom Badge index and the Verdant Lash TM row.

So what is missing is the CONNECTION: nothing today awards a badge or grants a
reward when a leader is beaten.

## ★ Prefer a by-ROW seam over a by-id one

`ZM-D-208` §2 ruled on exactly this shape one slice earlier and the reasoning
carries: a helper keyed on `ZM_TRAINER_ID` can only ever be exercised through the
shipped roster, so its coverage dies the moment content changes, while a helper
taking a `const ZM_TrainerData&` can be driven by a hand-built row and cannot
drift. `ZM_ApplyTrainerResultToGameState` already has both shapes for the same
reason. Follow it: make the reward path reachable from a row, so the units do not
depend on Fenna specifically remaining the first gym leader forever.

★ **AND DO NOT ASSERT A REWARD THE PLAYER CANNOT KEEP.** "Persists" is the word in
the Definition of Done and it is the whole point: a badge awarded into a mask that
is never written, or a move taught to a party member that is not saved, passes an
in-memory assertion and fails the player. Prove both through an actual save/load
round trip, not by re-reading the object you just mutated.

**Review — one BLOCKING finding, and it overturned the orchestrator**

`review.required` was true (risk MEDIUM + an ABSENCE claim). The absence claims all held:
`ZM_GameState.h` and `ZM_SaveSchema.cpp` are absent from the diff, no `.zscen` is in it, the
round trip genuinely re-decodes into a fresh `ZM_GameState`, and the by-ROW fixture would still
pass with Fenna deleted from the roster.

**The blocking finding was a judgement I had already accepted and recorded as fact.** The TM
grant was ungated, so a repeat win stacked a second copy. I had reasoned — following the
worker — that this matched prize money, which stacks under ZM-D-135. **The precedent does not
transfer.** ZM-D-208's correction states money's cause: it pays again *because* ZM-D-135
forbids a new `ZM_GameState` member to record "already paid". For an item that cause is absent
— `m_xBag` IS the record and `ZM_Bag::Has` answers it — so "adds no state" was an argument
FOR gating that I had recorded as one against. And the consequence was not cosmetic: Verdant
Lash is `m_bConsumable = false`, so a second copy's only use is `ZM_ShopSell` at its 500 sell
price — a farmable prize, the precise shape the per-trainer defeat flag exists to forbid.

Fixed at fix-forward 1 of 3, content-only, so the 3419 pin measured before it still stands and
the verify run re-confirmed it. Recorded as **ZM-D-214**, with **ZM-D-213 corrected in place**.

Four non-blocking findings were also taken: the by-ROW unit now uses a TM *distinct* from
Fenna's so the item half of "row-driven, not hardcoded" is proven rather than assumed; the
nine-column legend and the SC5 call-site comment were both stale; and the "load-bearing"
default initializers had **zero coverage** — deleting them left every gate green — now closed
by a `static_assert` rather than a comment.
