## Goal

ZEN-85 retired a stale rule from the engine-level docs on 2026-09-21: *"never
build the whole solution — the aux tools (FluxCompiler / font libs) present in
the sln are pre-existing-red in `ToolsEnabled=True`."* It is false. Measured on
that ticket, `FluxCompiler`, `FreeType`, `msdfgen` and `msdf-atlas-gen` all
build green in `Vulkan_vs2022_Debug_Win64_True`, and both
`Build/zenith_engine_win64.sln` and `Games/Combat/combat_win64.sln` build whole
with zero errors. `Docs/BuildSystem.md`'s "Whole-solution build status (ZEN-85,
2026-09-21)" subsection carries the full measurement.

Zenithmon's own living docs repeat the retired claim as game-local guidance, and
ZEN-85 deliberately did not touch them: editing `Games/Zenithmon/**` would have
unioned Zenithmon's whole gate list onto an engine documentation ticket. The
three sites, surveyed on ZEN-85:

- `Games/Zenithmon/Docs/AgentBriefing.md` — two sites (around lines 46-47 and
  562-563), both asserting the aux tools are pre-existing-red in ToolsEnabled
  configs. This is the file every Zenithmon loop worker reads, so a false claim
  here has the widest blast radius of the three.
- `Games/Zenithmon/Docs/BuildEnvironment.md` — two sites (around lines 85 and
  258), the second a troubleshooting row whose stated cause ("the aux tools are
  pre-existing-red") is the false half.
- `Games/Zenithmon/Docs/OrchestratorPlaybook.md` — one site (around line 247).

Line numbers are from 2026-09-21 and may have drifted; grep for
`pre-existing-red` and `whole s` rather than trusting them.

`Games/Zenithmon/Docs/StartPrompts.md` also says "never the whole sln" twice,
but only as a build-command policy line and without the false cause. That is
still good advice — `/t:Zenithmon` remains the recommended default — so leave it
unless the wording implies the projects are broken.

Keep `/t:Zenithmon` as the recommendation everywhere. What changes is the stated
REASON: it is a speed and scoping preference, not a workaround for red projects.
Do not overcorrect into telling anyone to build whole solutions by default.
