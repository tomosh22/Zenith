Both Definition-of-Done items are satisfied by R1-2 phase 2 step 2, which `Status.md` records as *"the measured-ground split: registry 65 -> 67 (the two region ground oracles)"*.

- [x] **Both constants re-derived from a measured oracle and frozen.** `fZM_ROUTE1_PROVISIONAL_GROUND_Y` and its Thornacre twin **no longer exist** — a repo-wide grep returns nothing. Each region now carries a deliberate two-part split, with the headers warning against collapsing them back into one scalar:
  - `fZM_ROUTE1_RECIPE_TARGET_GROUND_Y = 26.0f` / `fZM_THORNACRE_RECIPE_TARGET_GROUND_Y = 28.0f` — recipe MIRRORS, exact, explicitly *"NEVER GIVE THIS CONSTANT A MEASURED VALUE"*;
  - `axZM_ROUTE1_GROUND_SAMPLES` / `axZM_THORNACRE_GROUND_SAMPLES` — the MEASURED surface, one row per column.
- [x] **A unit locks the measured value.** `ZM_Route1GroundTruth_Test` and `ZM_ThornacreGroundTruth_Test` (`Tests/ZM_AutoTests_RouteGround.cpp`) cast a real downward ray at every column anchor. Both observed **PASS** in a full `zenith test Zenithmon --headless` run today (67 passed, 0 failed), alongside the placement units in `ZM_Tests_Route1Placement.cpp` / `ZM_Tests_ThornacrePlacement.cpp` that read the sample tables.

**The `blocked by ZM-49` link was wrong, and worth understanding rather than just removing.** E8's gap is that a raycast cannot answer at **authoring** time — it needs the terrain physics body streamed in, and it cannot see past a body standing on the surface. But these oracles run at **runtime**, inside an automated test with the scene loaded, where a downward ray works fine. R1-2 solved the problem in the regime where the old tool still worked, so the dependency never actually bound.

Note also that ZM-49's TIER 1 query would have been the *wrong* instrument here anyway for anything visual: it answers the 4 m collision surface, not the 1 m rendered one.
