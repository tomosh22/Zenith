## Goal
`MasterPlan.md` verification: *"4-config matrix check at major gates (Debug/Release x True/False; D3D12_False link check) per repo norm"*, and the memory that CI builds `Vulkan_` only, so backend rot hides until a `Null_` or `D3D12_` build. The ship-candidate gate is the last place to find it. Build and boot every win64 configuration of Zenithmon and record the result.

Scope: `zenith build Zenithmon --config <C>` for every row of the config table (`Vulkan_` and `Null_` in Debug and Release, Tools True and False; `D3D12_vs2022_Debug_Win64_False` as the link proof), then for each buildable-and-bootable row `zenith test Zenithmon --headless` or the windowed registry as the backend allows, plus `zenith package Zenithmon` staging a relocatable build and booting it from `dist/` with `--assets-root`. The `_False` (no tools) configs are known to be historically rough (Build oddities memory); every failure is a ticket, not a note. Android is out of this ticket's scope (the emulator run needs a person and its own ticket if the ship gate wants it).

## Definition of Done
- [ ] Every win64 configuration builds, and every bootable one reaches "Unit tests complete" with zero failures or a filed ticket names the failure
- [ ] The D3D12 link proof is green
- [ ] A packaged build boots from `dist/` with `--assets-root`
- [ ] The matrix results table is in `Docs/Status.md` beside the S12 gate
