## Goal
Two documents describe a file-time refusal that does not exist.

Root `CLAUDE.md:801-826` and the tick protocol (`TICK.md`, lines 640-646) say that `zagent create` refuses at file time any ticket that would be immediately claimable (unassigned, no `needs-human`) in three cases:
- its body would fail the contract;
- it carries its own `## Gates`;
- its Definition of Done names a protected path.

`CLAUDE.md:797-798` adds that a ticket without complexity or risk *"comes back `contractValid: false` rather than being guessed at"*.

None of this is implemented:
- `create` (`Tools/Vault/cli/write.mjs:1165-1252`) validates only usage, enums, the `approved` and `integration-conflict` labels, block reasons and graph references.
- It never calls `evaluateContract` (`Tools/Vault/cli/compat.mjs:763`).
- It silently defaults `--complexity` to MODERATE and `--risk` to LOW (`write.mjs:1172-1173`).

The docs describe how the board behaved before the Vault cutover. The contract evaluator this refusal needs already exists, and `show`, `check` and `claim` already run it.

The refusal must catch the following, because nothing else does until a claim has been spent:
- a body with no `## Goal`;
- a body with no Definition of Done checkbox;
- a missing or unconfigured category (`categoryContractError`, `Tools/Vault/cli/legacy-pure/routing.mjs:125-137`);
- a Definition of Done that names a protected path (`reachabilityError`, `Tools/Vault/cli/legacy-pure/contract.mjs`);
- a `Gates` heading at level 2 or 3.

The `Gates` refusal applies at create time only. `Tools/Vault/cli/legacy-pure/ticket.mjs:31-33` parses such a heading into ticket gates, and those gates replace the category's (`legacy-pure/routing.mjs:79-81`). `validateTicket` deliberately accepts them at claim time for older tickets, so the claim-time behaviour stays as it is.

Some tickets are not immediately claimable, and they keep filing exactly as today:
- a blocked ticket;
- an EPIC;
- an assigned ticket;
- a ticket created with a status other than To Do;
- a ticket labelled `needs-human`.

Advisory findings are not refusals: a Goal that names a protected path, a board-reference warning, a marker warning, or the DoD blast-radius warning.

The web UI's create builds the same CLI command (`Tools/Vault/web/issues/model.js:488-520`). It therefore inherits the refusal, and it surfaces the CLI's message.

## Definition of Done
- [ ] `zagent create` exits 4 and writes nothing for a To Do, unassigned, non-EPIC ticket without `needs-human` in each of these cases:
      the body has no Goal;
      the body has no DoD checkbox;
      the body has a `Gates` heading at level 2 or 3;
      the DoD names a protected path, and the message names both the path and the pattern;
      the category is missing or not configured.
- [ ] The same create exits 4 and names the missing flag when `--complexity` or `--risk` is omitted, instead of storing a default
- [ ] The same bodies file with exit 0 when the ticket carries any one of: `--label needs-human`, an `--assignee`, `--type EPIC`, or a `--status` other than To Do
- [ ] A ticket whose only findings are advisory still files with exit 0. Advisory findings are: a Goal that names a protected path, a board-reference warning, a marker warning, or the blast-radius warning
- [ ] New cases in `Tools/Vault/test/claim-rulings-and-create-scan.test.mjs` exercise each refusal and each exemption above
- [ ] Existing suites that create fixture tickets still pass, adjusted only to pass a valid body, category, complexity and risk
- [ ] The `create` row of `Tools/Vault/spec/command-matrix.md` describes the file-time refusals
- [ ] `npm test` in `Tools/Vault` and the rest of the Tooling gate list are green
