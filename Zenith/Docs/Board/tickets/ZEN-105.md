## Goal

ZEN-92 removed the hardcoded `C:/tmp/` capture destination from
`Test_MaterialEditorLivePreview`, on the reasoning it states: *"it is outside
the repo, outside `Build/artifacts/`, and therefore outside anything the
artifact conventions or `.gitignore` govern."*

That reasoning applies unchanged to **eight more test files that still write
captures there**, and ZEN-92's Definition of Done named only the two harnesses
it was scoped to, so they were left alone. Measured 2026-09-21 after ZEN-92
landed:

| file | paths |
|---|---|
| `Games/DevilsPlayground/Tests/MaterialEntityShowcase.cpp` | `C:/tmp/dp_mat_%s.tga` |
| `Games/DevilsPlayground/Tests/Test_MaterialShowcase.cpp` | `C:/tmp/mat_showcase_%s.tga` |
| `Games/DevilsPlayground/Tests/Test_DPCamera_ModeTransition.cpp` | `C:/tmp/dp_camera_thirdperson.tga` |
| `Games/DevilsPlayground/Tests/Test_DPFogPass_VisualOutput.cpp` | `C:/tmp/dp_fog_memory_A.tga`, `..._B.tga` |
| `Games/DevilsPlayground/Tests/Test_DP_LiminalHub_Spend.cpp` | `C:/tmp/dp_liminal_hub.tga` |
| `Games/DevilsPlayground/Tests/Test_DP_Minimap_RevealAndTracking.cpp` | `C:/tmp/dp_minimap.tga` |
| `Games/RenderTest/Tests/GrassShowcase.cpp` | `C:/tmp/grass_showcase_%s.tga`, `..._shadows_%s.tga`, `..._displacement_trail.tga` |
| `Games/RenderTest/Tests/MaterialBattleTest.cpp` | `C:/tmp/mat_battle_%s.tga` |

Roughly ten capture paths across eight files. Every one has the same three
problems ZEN-92 names: outside the repo, ungoverned by `.gitignore`, and a fixed
destination that silently overwrites the previous run rather than keeping a
BEFORE and an AFTER set apart.

**The mechanism to use already exists and is engine-owned**, added by ZEN-92:
`--capture-tag <tag>` via `Zenith_CommandLine::GetCaptureTag()`, with `"run"` as
the no-tag default. `Games/Zenithmon/Tests/ZM_AnimEditorShowcase.cpp`'s
`CaptureDir()` and `Games/DevilsPlayground/Tests/Test_MaterialEditorLivePreview.cpp`'s
`CaptureDir()` are both worked examples: derive the repo root from
`GAME_ASSETS_DIR / ".." / ".." / ".."` through `weakly_canonical` (so it resolves
regardless of the process working directory), then
`Build/artifacts/<game>/<area>/<tag>/`, and fail loudly if the directory cannot
be created.

★ **Three `C:/tmp` references are NOT write sites and must be left exactly as
they are** — they are string fixtures in parser tests that never touch the
filesystem:

- `Zenith/Core/Zenith_CommandLine.Tests.inl:142` — `"C:/tmp/shot.tga"` as a
  `--screenshot` argv value
- `Zenith/Editor/Zenith_AnimationDocument.Tests.inl:558` — asserts
  `BuildAuthoredAssetPath("C:/tmp/loose.zanim")` is empty
- `Zenith/Profiling/Zenith_Profiling.Tests.inl:579` — asserts
  `ResolveBootProfileDumpArg` parses a `=`-joined path

A grep-and-replace sweep that does not distinguish these will break three unit
tests, and two of them exist specifically to pin how an absolute path outside the
repo is handled.

Several of these harnesses are `requiresGraphics` and therefore skipped by every
headless gate, so a green gate run proves only that they still COMPILE. Whichever
are run to verify, run them by hand and say so.

## Definition of Done

- [ ] Every capture WRITE under `Games/**` targets `Build/artifacts/`, with no
      `C:/tmp` destination left
- [ ] Each converted harness takes the existing `--capture-tag` and writes under
      a per-tag directory, defaulting to `run` when no tag is given
- [ ] Each fails loudly if its output directory cannot be created, rather than
      writing nowhere
- [ ] The three parser-test string fixtures listed above are unchanged
- [ ] Every affected game's pinned baseline bumped from an OBSERVED run, if the
      change adds or removes a unit
