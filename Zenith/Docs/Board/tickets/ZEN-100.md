## Goal

`Zenith.h` is the precompiled-header master header: every engine `.cpp` begins
`#include "Zenith.h"`. Its transitive closure is **219 headers, of which 202 are
glm** — so every translation unit in the engine, and every one of the 13 binary
`.pch` files the library split now produces, pays for the entire glm surface
whether it does maths or not.

The cost is measurable. A win64 `Zenith.pch` is 119 MB in `Debug_True` and
192 MB in `Release_True`. The library split deliberately withheld a PCH from
every library under 4 translation units precisely because a 1-TU library with a
PCH parses glm twice instead of once — a rule that exists only to work around
this header's weight.

Introduce a forward-declaration header (`Zenith_MathsFwd.h` or similar) carrying
the `Zenith_Maths::` type names without the glm definitions, and move `Zenith.h`
onto it. Translation units that genuinely need the full glm surface include the
heavy header explicitly, the way `Flux_BackendTypes.h` is the explicit heavy
seam beside the light `Flux_Fwd.h`. This is the real fix that the >=4-TU PCH
rule is only a mitigation for.

Measure before and after: the header count in `Zenith.h`'s closure, the size of
one representative `.pch`, and a cold build of one game in
`Vulkan_vs2022_Debug_Win64_True`.

## Definition of Done

- [ ] `Zenith.h`'s transitive closure no longer pulls the full glm surface, and the measured header count is recorded in the commit message
- [ ] Every translation unit that needs full glm types includes the heavy header explicitly rather than relying on the precompiled header
- [ ] A representative `Zenith.pch` is measurably smaller, with the before/after figures recorded
- [ ] The engine and every game build green on Vulkan, Null, D3D12 and AGDE
- [ ] Every affected game's pinned unit baseline is bumped from an OBSERVED run, or confirmed unchanged
