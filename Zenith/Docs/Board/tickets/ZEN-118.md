## Goal
Root `CLAUDE.md` and two game board guides make three claims about the board that it does not do. In each case the code is right and the doc is wrong.

**1. Bare `zagent next` walks every board.** `CLAUDE.md:450-452` says: *"`zagent next` with no `--project` walks every declared board in declaration order and reports 'nothing to claim' only when every one is empty."* In fact `queueCandidate` (`Tools/Vault/cli/write.mjs:638-675`) selects ONE project, in this order: `--project`, else the lane's own project, else the project file's top-level `project`, which is ZEN (`zagent.project.json:44`). `queue` does the same (`projectSelection`, `Tools/Vault/cli/read.js:355-367, 460-464`).

The code should not change, for three reasons:
- The spec of record, `Tools/Vault/spec/command-matrix.md:186`, promises only "the first eligible QueueRow".
- ZEN-113's lane scoping builds on the single-project default.
- If the main checkout walked every board, it could claim work in a project that has its own registered lane.

So a bare `/tick` in the main checkout reaches ZEN only, and other boards need `/tick <PROJECT>` or a lane. `CLAUDE.md:590` (*"one tick against the head of whichever board has work"*) and `:593` (*"until the queues empty"*) need the same correction.

**2. An `OUT OF STAGE` line.** `CLAUDE.md:921-923` says: *"`zagent check` shows both: exit 4 for the epic, an `OUT OF STAGE` line for the sprint."* Nothing emits `OUT OF STAGE`: `git grep` over `Tools/` finds no emitter. The real signal has two parts:
- the payload's `sprint: {name, status, continuous, inScope}` on `show`, `check` and `claim`;
- `check.queue.reason`, which reads *"it is in <sprint> (PLANNED), not the active sprint"* (`Tools/Vault/cli/compat.mjs:810`).

Measured on 2026-10-16: `zagent show HE-5 --json` returns `"sprint":{"name":"HE P0 — Foundations","status":"PLANNED","continuous":false,"inScope":false}`. `Games/Foundry/Docs/Board.md:40` and `Games/Undervault/Docs/Board.md:39` repeat the claim (*"every ticket shows `OUT OF STAGE` … (`zagent check <KEY>` prints it)"*).

**3. The `--category` list.** `CLAUDE.md:780-781` lists the `--category` values as Zenithmon, Engine, DevilsPlayground, ScriptTest, Undervault, Hearth and Foundry. The project file also declares `Tooling` (`zagent.project.json:393`). Tooling has no `project` key, so it files on ZEN.

**Out of scope for this ticket:**
- The same `next` and `OUT OF STAGE` claims in the tick protocol, and in `Games/Hearth/Docs/Board.md:38`, are handled by a separate ticket. The protocol is a protected path. A diff under `Games/Hearth/**` unions in Hearth gates that cannot pass until HE-5's scaffold lands.
- `CLAUDE.md:724` (the `sprint` row) is corrected by the sprint-gate enforcement ticket.
- `CLAUDE.md:797-826` (create-time refusal) becomes true once the create-refusal ticket lands, so leave it as it is.

**Gate cost.** A diff under `Games/Foundry/**` and `Games/Undervault/**` also unions in the Foundry and Undervault category gates: regen, plus a build and test of each game.
