## Goal
`zagent.project.json:104` declares `languageConventions`, the C++ clause: *"No std:: containers; every .cpp starts with #include "Zenith.h"; tabs; braces on new lines; Zenith_Assert is the real assert (ZENITH_ASSERT is an empty marker)."* `Tools/Vault/cli/legacy-pure/routing.mjs:89-93` composes it into every category's conventions unless the category sets `suppressLanguageConventions: true`. Only Tooling sets it (`zagent.project.json:459`).

The clause never reaches production routing. `Tools/Vault/cli/compat.mjs:285-288` (`PROJECT_FILE_OWNED`) lists `baseBranch`, `branching`, `merge`, `conventions`, `cleanup`, `reviewOn`, `workerTools`, `categories`, `conventionDocs` and `protectedPaths`. `languageConventions` is not in the list, so `withProjectFileOverlay` (`compat.mjs:299-311`) never copies it onto `policy.resolved.projects.*`. None of the six resolved project entries in the Vault config (`policy.resolved.projects`) carries it either.

Measured on 2026-10-16 at `268b8ef6`:
- `zagent show ZEN-112 --json` (category Engine) returns conventions with the universal clause and Engine's own text, and no "No std::".
- `zagent show HE-5 --json` (category Hearth) returns the universal clause and Hearth's text only.

`build_prompt.ps1` inlines `conventions` verbatim, so every C++ ticket's worker prompt has been missing the C++ rules.

The test meant to pin this cannot see the gap. `Tools/Vault/test/category-routing.test.mjs:52-55` (`realConfig()`) passes the raw on-disk file straight to `resolveRules()`, so it never goes through `legacyConfigOf()` or the overlay that production uses. Its comment at `:44-50` says the file's top-level fields "are exactly what PROJECT_FILE_OWNED overlays", which is false for this key.

Make `languageConventions` project-file-owned, the way `conventions` already is. Add a test that goes through the production load path.
