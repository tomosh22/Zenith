## Goal
These statements are stale, and the files that carry them are protected. `vault.config.json` `policy.board.guardrails.protectedPaths` protects `Tools/zagent/protocol/**`, `Tools/zagent/Build-HarnessArtifacts.ps1`, `.claude/**`, `.codex/**` and `.opencode/**`, so `zagent guard` refuses an agent diff that touches them. One game guide is also included here: it is not protected, but its category gates cannot pass yet. In every case the code is right and the doc is wrong.

**Stale statements in `Tools/zagent/protocol/TICK.md`:**

1. **Exit 7.** `:173-177` says *"Exit 7 is new … it means the board was unreachable"*, and the exit table has a matching row at `:602` (`| 7 | Board unreachable | …`). Nothing produces exit 7. `EXIT_CODES` (`Tools/Vault/cli/compat.mjs:30-38`) holds 0, 1 and 5; WriteError adds 3, 4 and 6. Root `CLAUDE.md` already says that there is no distinct board-unreachable code.
2. **Two backends.** `:181-183` says every `zagent` call writes `last.exit` *"on **either backend**"*: the Vault client and the PowerShell one in `Tools/zagent/zagent.ps1`. There is one backend. `zagent.ps1` is a dispatch shim that execs `Tools/Vault/cli/client.mjs`.
3. **Bare `next` walks every project.** `:558-559` says *"`$1` absent → queue, every project this repo declares, in declaration order"*, and `:568-572` says *"with no `--project`, `next` walks all three declared projects"*. In fact `next` selects ONE project: `--project`, else the lane's own project, else the checkout default ZEN (`queueCandidate`, `Tools/Vault/cli/write.mjs:638-675`). The spec of record, `Tools/Vault/spec/command-matrix.md:186`, matches the code.
4. **An `OUT OF STAGE` line.** `:705-708` says *"`check`/`show` print an `OUT OF STAGE` line"*, and `:759-761` says *"flagged `OUT OF STAGE` on a targeted claim"*. Nothing emits that string. The signal is `sprint.inScope: false` on the show, check and claim payload, together with `check.queue.reason` (*"it is in <sprint> (PLANNED), not the active sprint"*, `compat.mjs:810`).
5. **The third review term.** Step 6.3 at `:1666-1675` says *"A THIRD TERM BELONGS IN THAT OR AND IS NOT THERE YET … Until the board computes it"*. The board does compute it:
   - `reviewOf` (`compat.mjs:693-717`) passes the category's decision-log text to `reviewDecision` (`Tools/Vault/cli/legacy-pure/ticket.mjs:110-`);
   - the third term there matches governing rulings;
   - `Tools/Vault/test/claim-rulings-and-create-scan.test.mjs` section F pins it.

No edit is needed at `:640-646` (create refuses at file time). That statement becomes true when the create-refusal ticket lands.
