# WORLD design: tests

Section file of `Zenith2/Docs/Design/WORLD.md`. It lists every WORLD test target, every named test with the case it asserts, the fixtures and how they are generated, the seams the tests use, and the gate step that runs each group. Test IDs follow `Test_<Type>_<Behaviour>` for the doctest case `"<Library>/<Type>/<Behaviour>"` (`Zenith2/Docs/Contracts.md` → "Tests and code hygiene gates"). Names are checked unique programme-wide (TEST-NAME-UNIQUE); WORLD's are `Test_World<WORLD type>_…` (`Test_WorldDocument_`, `Test_WorldPartition_`, `Test_WorldEditor_` and the others below), which today collide with none, although the `World` prefix alone guarantees nothing (ECS has `Test_WorldRegistry_*` and `Test_Worlds_*`, GAME `Test_WorldTransition_*`). Workers write these tests; no test is run or recorded by a worker (WORKER-EVIDENCE), and no binary file is committed (Q55). Every expected value a test asserts is written in this file or derivable from it by hand; no test needs a double of a concrete type (FINAL-DOUBLES): the seams are the interfaces `Zenith_WorldSourceAccess`, `Zenith_WorldCellContributor` and `Zenith_WorldMeshGeometrySource`, each with production implementations and a test implementation.

| Target | Sources | Gate step | Presets |

| `Zenith_Integration_WorldAuthoring` | `Zenith2/Tests/WorldAuthoring/*.cpp`, declared `zenith_add_integration_tests(WorldAuthoring DEPENDS ZenithRuntime ZenithStreaming ZenithScene ZenithECS_Custom ZenithPhysics ZenithPhysics_Jolt ZenithAuthoring ZenithContentCore SUPPORTED ZENITH_TOOLS_HOST)` (`Zenith2/Docs/Architecture/BuildSystem.md` → "Tools, benchmarks and integration suites") | `Test` | `win` |

Every target is `ZENITH_TOOLS_HOST`, so none builds in `win-asan` or `linux-tsan`. WORLD's concurrency is limited to independent work items writing disjoint slots: the worker-count invariance tests drive them through `Zenith_JobSystem::RunRoot` with a `ParallelFor` over the item indices on job systems of 1, 2, 8 and all workers (the test's main thread created the job system, as `RunRoot` requires, `Zenith2/Docs/Design/JOBS/PublicAPI.md` → "Zenith_JobSystem header") and inline, and a race would show as a byte difference; ZenithJobs' own races are covered under `linux-tsan`.
