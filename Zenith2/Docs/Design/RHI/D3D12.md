# RHI design: the D3D12 backend

This file is part of the RHI design family. The entry document is `Zenith2/Docs/Design/RHI.md`. It specifies `ZenithRHI_D3D12`: how it realises the public API of `Zenith2/Docs/Design/RHI/PublicAPI.md` on D3D12 with the Agility SDK, Shader Model 6.6, Enhanced Barriers and D3D12MA, on Windows alone ([Z2-N-REND-026]). Every D3D12, DXGI and D3D12MA header is included from `Zenith2/Engine/ZenithRHI_D3D12/Internal/` alone ([Z2-N-CONTRACT-043]).

## Scope of this file

The specification elaborated is `Zenith2/Docs/Rendering.md → "GPU baseline and profiles"` (table "D3D12 baseline", the format rows), `Zenith2/Docs/Rendering.md → "Binding model"` (heading "D3D12 heap realisation", the draw ID), `Zenith2/Docs/Rendering/RenderGraph.md → "Barrier emission"`, `Zenith2/Docs/Rendering/GpuResources.md → "Swapchain recreation"` and "Device loss", and `Zenith2/Docs/Rendering/ShaderSystem.md → "Persistent pipeline caches"`.

## Agility SDK loading

The executable exports `D3D12SDKVersion` and `D3D12SDKPath` from the constants of `Zenith_RHI_D3D12.h` (`Zenith2/Docs/Design/RHI/PublicAPIDevice.md → "Backend factory headers"`), and the build stages `D3D12Core.dll` (and `d3d12SDKLayers.dll` outside Shipping) into `<bin>/D3D12/`. The first D3D12 call (`D3D12GetDebugInterface` or `D3D12CreateDevice`) makes the OS loader pick the staged runtime. After device creation, `ID3D12DeviceConfiguration::GetDesc()` reports `SDKVersion`; a value different from `uZENITH_D3D12_AGILITY_SDK_VERSION` means the system runtime was loaded instead (the staged files are missing or the OS refused the redirect), which fails device creation with `ZENITH_RHI_ERROR_LOADER_UNAVAILABLE` and the message `rhi.d3d12: Agility SDK <expected> not loaded (runtime reports <actual>); check <bin>\D3D12\D3D12Core.dll`, because enhanced barriers need the pinned runtime ([Z2-N-REND-024] table, last row). The loaded version is `m_uAgilitySDKVersion` of the capabilities and part of the pipeline-cache key.

## Adapter selection

| Step | Call |
|---|---|
| 1 | `CreateDXGIFactory2(DXGI_CREATE_FACTORY_DEBUG when validation is on)` → `IDXGIFactory6` |
| 2 | `SOFTWARE` preference: `EnumWarpAdapter`; otherwise `EnumAdapterByGpuPreference(i, DXGI_GPU_PREFERENCE_HIGH_PERFORMANCE)` for i = 0 … until `DXGI_ERROR_NOT_FOUND`, skipping `DXGI_ADAPTER_FLAG_SOFTWARE` adapters |
| 3 | `m_szAdapterFilter` against `DXGI_ADAPTER_DESC3::Description` (UTF-16 converted to UTF-8), case-insensitively |
| 4 | per candidate: `D3D12CreateDevice(adapter, D3D_FEATURE_LEVEL_12_0, IID_PPV_ARGS(&device))`, then the baseline checks below; a failing candidate is released and its refusal line recorded |
| 5 | the first passing candidate wins; none: `PROFILE_UNSUPPORTED` when some candidate failed a row, `NO_ADAPTER` when there was no candidate |

## Baseline checks

Each row of `Zenith2/Docs/Rendering.md → "GPU baseline and profiles"` (table "D3D12 baseline") is one `CheckFeatureSupport` query:

| Row | Query and pass condition |
|---|---|
| Shader Model 6.6 | `D3D12_FEATURE_SHADER_MODEL` with `HighestShaderModel = D3D_SHADER_MODEL_6_6` returns ≥ 6.6 |
| resource binding tier 3 | `D3D12_FEATURE_D3D12_OPTIONS::ResourceBindingTier == D3D12_RESOURCE_BINDING_TIER_3` |
| Enhanced Barriers | `D3D12_FEATURE_D3D12_OPTIONS12::EnhancedBarriersSupported` |
| native 16-bit ops | `D3D12_FEATURE_D3D12_OPTIONS4::Native16BitShaderOpsSupported` |
| wave intrinsics | `D3D12_FEATURE_D3D12_OPTIONS1::WaveOps` |
| typed UAV loads | `D3D12_FEATURE_FORMAT_SUPPORT` `Support2 & D3D12_FORMAT_SUPPORT2_UAV_TYPED_LOAD` for `R11G11B10_FLOAT`, `R16G16B16A16_FLOAT`, `R16G16_FLOAT` |
| `WriteBufferImmediate` | `QueryInterface(ID3D12GraphicsCommandList2)` on a probe list succeeds |
| Agility SDK version | "Agility SDK loading" above |
| format features | for each row of `axZENITH_RHI_FORMAT_FEATURES` whose platform mask includes Windows and whose DXGI format is not `-`: `D3D12_FEATURE_FORMAT_SUPPORT`, `Support1` bits `TEXTURE2D \| SHADER_SAMPLE` (S), `SHADER_SAMPLE` with linear filter implied by `SHADER_SAMPLE` for non-integer formats (L), `RENDER_TARGET` (C), `BLENDABLE` (B), `TYPED_UNORDERED_ACCESS_VIEW` plus `Support2 UAV_TYPED_STORE` (W), `Support2 UAV_TYPED_LOAD` (T), `DEPTH_STENCIL` (D) ([Z2-N-REND-037]) |
| heap capacities | the sum of the four space capacities ≤ 1,000,000 (tier 3's shader-visible heap maximum) |

The refusal line, one per refused adapter:

```text
rhi: D3D12 adapter '<Description>' (vendor 0x<VVVV> device 0x<DDDD> driver <UMD version>) does not meet the D3D12 baseline: failed <row>[, <row>…]
<row> := shader model <have> < 6.6 | resource binding tier <have> < 3 | enhanced barriers | native 16-bit shader ops | wave ops | format <DXGI_name> <letters missing> | agility sdk <have> != <pinned> | heap capacity <sum> > 1000000
```

The UMD version is `IDXGIAdapter::CheckInterfaceSupport(__uuidof(IDXGIDevice))`'s `LARGE_INTEGER` printed as `a.b.c.d`; it is also `m_ulDriverVersion`. The capability fill: `m_bDepthD24S8` from the `D24_UNORM_S8_UINT` format row; `m_bMeshShaders` from `D3D12_FEATURE_D3D12_OPTIONS7::MeshShaderTier ≥ TIER_1`; `m_bAsyncComputeQueue` and `m_bCopyQueue` true (D3D12 always creates compute and copy queues); `m_auTimestampValidBits` 64 on graphics and compute, and on copy 64 when `D3D12_FEATURE_D3D12_OPTIONS3::CopyQueueTimestampQueriesSupported` else 0; `m_bMemoryBudget` true; `m_bCalibratedTimestamps` true; `m_bPresentWait` false (the latency waitable object serves pacing); `m_bDeviceFaultInfo` true when DRED is enabled; `m_uHeapTier` from `D3D12_FEATURE_D3D12_OPTIONS::ResourceHeapTier`; subgroup sizes from `D3D12_FEATURE_D3D12_OPTIONS1::WaveLaneCountMin/Max`; `m_ulDeviceLocalBytes` from `DedicatedVideoMemory`; `m_bSoftwareAdapter` for WARP; `m_bTearingSupported` from `DXGI_FEATURE_PRESENT_ALLOW_TEARING`.

## Queues and fences

One `ID3D12CommandQueue` per class (`DIRECT`, `COMPUTE`, `COPY`), priority normal, and one `ID3D12Fence` per queue (initial value 0) as its timeline. `Submit` takes the queue's lock (400), calls `Wait(fence, value)` on the queue for each timeline wait, `ExecuteCommandLists` with the batch's lists, then `Signal(fence, last + 1)`. `WaitCPU` uses `SetEventOnCompletion` with a per-thread auto-reset event created at device creation for the render-submit thread and the main thread, and `WaitForSingleObject` with the timeout; `WAIT_TIMEOUT` is `ZENITH_RHI_WAIT_STATUS_TIMEOUT`, after which `GetDeviceRemovedReason` reports loss. `WaitIdle(timeout)` is that `WaitCPU` on each queue's fence for its last-signalled value, one queue at a time. The swapchain's back buffers need no semaphores: queue order and DXGI's own fence cover acquire and present ([Z2-N-REND-487]).

## Descriptor heaps

<!-- elaboration: the RTV and DSV capacities -->
| Heap | Type | Shader visible | Capacity | Layout |
|---|---|---|---|---|
| global | `CBV_SRV_UAV` | yes | sum of the four space capacities | the four spaces contiguous, in `Zenith_RHIDescriptorSpace` order; each space's base offset is the sum of the preceding capacities, emitted into `Bindless.slang` per tier ([Z2-N-REND-055]) |
| render targets | `RTV` | no | 8,192 | one descriptor per (texture, mip, layer, view format) attachment view, allocated at the view's first use, freed at the texture's retirement |
| depth stencil | `DSV` | no | 2,048 | as RTV, with a read-only variant (`D3D12_DSV_FLAG_READ_ONLY_DEPTH \| READ_ONLY_STENCIL`) |

`Zenith_RHIDescriptorHeap::Write` calls `CreateShaderResourceView` or `CreateUnorderedAccessView` directly into the slot's CPU handle (`heapStart + (spaceBase + index) × increment`); writes to distinct slots are free-threaded, so no lock is taken on D3D12. Depth formats are viewed through `R32_FLOAT_X8X24_TYPELESS` and `R24_UNORM_X8_TYPELESS`; the GB0 mutable image is created `R8G8B8A8_TYPELESS` with SRV `UNORM_SRGB`, RTV `UNORM_SRGB` and UAV `UNORM` ([Z2-N-REND-039]). Static samplers are not descriptors: they are the root signature's sixteen entries.

## Root signature and command signatures

The global root signature is the table of `Zenith2/Docs/Rendering.md → "Binding model"` (heading "D3D12 heap realisation"): parameter 0 two 32-bit constants at `b0, space0` (the constant buffer Slang reflects on the D3D target for every entry point's `uniform Flux_PushConstants` parameter, declared with no `register`; `ZenithShaderCompiler` refuses a program that reflects another register, space or size with `ZSC_ERROR_PUSH_CONSTANTS`, `Zenith2/Docs/Design/RPROD/PSO.md → "Compiler pipeline"`, step 6), parameter 1 one 32-bit constant at `b1, space0` (the draw ID, declared for the D3D target in `Zenith2/Shaders/Common/Params.slang` beside `Flux_PushConstants` and read by `Common/DrawID.slang`'s `Flux_DrawIndex()`), sixteen static samplers `s0`–`s15`, flags `CBV_SRV_UAV_HEAP_DIRECTLY_INDEXED | ALLOW_INPUT_ASSEMBLER_INPUT_LAYOUT`, serialised with `D3D12SerializeVersionedRootSignature` (version 1.1) once at creation.

| Command signature | Arguments | Stride |
|---|---|---|
| indexed draw | `D3D12_INDIRECT_ARGUMENT_TYPE_CONSTANT` (root parameter 1, one value, destination offset 0), then `DRAW_INDEXED` | 24 |
| dispatch | `DISPATCH` | 12 |
| mesh dispatch | `DISPATCH_MESH` (created when mesh shaders are supported) | 12 |

`DrawIndexedIndirect(args, offset, count)` is `ExecuteIndirect(indexedSignature, count, args, offset, nullptr, 0)`; `DrawIndexedIndirectCount` passes the count buffer and offset ([Z2-N-REND-069]).

## Pipelines and the PSO library

- Graphics, compute and mesh PSOs are built as `D3D12_PIPELINE_STATE_STREAM_DESC` streams (root signature, shader bytecode, input layout from the attributes with semantic names and indices, rasterizer with `FrontCounterClockwise = TRUE`, depth-stencil `DEPTH_STENCIL_DESC1`, blend with `IndependentBlendEnable`, render-target formats, depth format, `SampleDesc{1, 0}`, primitive topology type) and created with `ID3D12Device2::CreatePipelineState`.
- A blob whose header is not `DXBC` container magic is `ZENITH_RHI_ERROR_SHADER_BLOB_INVALID`.
- The pipeline cache is an `ID3D12PipelineLibrary1` created with `CreatePipelineLibrary(payload)`; `D3D12_ERROR_DRIVER_VERSION_MISMATCH`, `D3D12_ERROR_ADAPTER_NOT_FOUND` or `E_INVALIDARG` create an empty library and set `WasLoadRejected` ([Z2-N-REND-205]).
- Creation with a cache: the entry name is `m_ulKeyHash` as 16 lowercase hexadecimal UTF-16 characters; `LoadPipeline(name, stream)` first (a hit sets `Zenith_RHIPipelineCreateResult::m_bCacheHit` and increments `RHI.Pipelines.CacheHits`, a miss `RHI.Pipelines.CacheMisses`); `E_INVALIDARG` (absent) creates the PSO and `StorePipeline(name, pso)` under `uLOCK_LEVEL_RHI_PIPELINE_LIBRARY` (470), because stores are serialised by the library; `E_INVALIDARG` from `StorePipeline` (a concurrent job stored the same name first) is ignored ([Z2-N-REND-204]).
- `Serialize` is `GetSerializedSize` then `Serialize` into the arena.

## Enhanced barrier translation

`Zenith_D3D12_ToSync`, `Zenith_D3D12_ToAccess` and `Zenith_D3D12_ToLayout` are the one mapping of the neutral vocabulary; with `Flux_ToRHIBarrier` they realise the D3D12 columns of `Zenith2/Docs/Rendering/RenderGraph.md → "Barrier state machine"` (table "Access states").

| Neutral stage | `D3D12_BARRIER_SYNC_` | Neutral access | `D3D12_BARRIER_ACCESS_` |
|---|---|---|---|
| `DRAW_INDIRECT` | `EXECUTE_INDIRECT` | `INDIRECT_COMMAND_READ` | `INDIRECT_ARGUMENT` |
| `INDEX_INPUT` | `INDEX_INPUT` | `INDEX_READ` | `INDEX_BUFFER` |
| `VERTEX_ATTRIBUTE_INPUT`, `VERTEX_SHADER`, `TASK_SHADER`, `MESH_SHADER` | `VERTEX_SHADING` | `VERTEX_ATTRIBUTE_READ` | `VERTEX_BUFFER` |
| `PIXEL_SHADER` | `PIXEL_SHADING` | `SHADER_SAMPLED_READ`, `SHADER_STORAGE_READ` (buffers) | `SHADER_RESOURCE` |
| `EARLY_FRAGMENT_TESTS`, `LATE_FRAGMENT_TESTS` | `DEPTH_STENCIL` | `SHADER_STORAGE_READ` (textures), `SHADER_STORAGE_WRITE` | `UNORDERED_ACCESS` |
| `COLOUR_ATTACHMENT_OUTPUT` | `RENDER_TARGET` | `COLOUR_ATTACHMENT_READ`, `COLOUR_ATTACHMENT_WRITE` | `RENDER_TARGET` |
| `COMPUTE_SHADER` | `COMPUTE_SHADING` | `DEPTH_STENCIL_READ` | `DEPTH_STENCIL_READ` |
| `COPY` | `COPY` | `DEPTH_STENCIL_WRITE` | `DEPTH_STENCIL_WRITE` |
| `CLEAR` | `RENDER_TARGET`, `DEPTH_STENCIL` or `CLEAR_UNORDERED_ACCESS_VIEW`, by the resource's usage | `TRANSFER_READ` / `TRANSFER_WRITE` | `COPY_SOURCE` / `COPY_DEST` |
| `ALL_COMMANDS` | `ALL` | `NONE` | `NO_ACCESS` |

| Neutral layout | `D3D12_BARRIER_LAYOUT_` |
|---|---|
| `UNDEFINED` | `UNDEFINED`, with `D3D12_TEXTURE_BARRIER_FLAG_DISCARD` when `m_bDiscard` |
| `GENERAL` | `UNORDERED_ACCESS` |
| `SHADER_READ` | `SHADER_RESOURCE` |
| `COLOUR_ATTACHMENT` | `RENDER_TARGET` |
| `DEPTH_STENCIL_WRITE`, `DEPTH_STENCIL_READ` | `DEPTH_STENCIL_WRITE`, `DEPTH_STENCIL_READ` |
| `TRANSFER_SRC`, `TRANSFER_DST` | `COPY_SOURCE`, `COPY_DEST` |
| `PRESENT` | `PRESENT` |
| `COMMON` | `COMMON` |
| `PERSISTENT_READ` | `GENERIC_READ` |

`DoRecordBarriers` builds one `D3D12_BARRIER_GROUP` of texture barriers (subresource range from the neutral range; depth formats name both planes), one of buffer barriers, one global group, and calls `ID3D12GraphicsCommandList7::Barrier` once ([Z2-N-REND-389]). A cross-queue texture transfer on D3D12 is a layout transition, not an ownership transfer: `Flux_ToRHIBarrier` places it on a queue whose type supports both layouts ([Z2-N-REND-391]); the backend records release and acquire halves as ordinary barriers with `SyncAfter = NONE` on the releasing queue and `SyncBefore = NONE` on the acquiring queue. Split barriers: `DoBeginSplit` records the batch with `SyncAfter = D3D12_BARRIER_SYNC_SPLIT`, `DoEndSplit` the same barriers with `SyncBefore = D3D12_BARRIER_SYNC_SPLIT` ([Z2-N-REND-393]).

## Memory through D3D12MA

`D3D12MA::CreateAllocator` with the device and adapter, `D3D12MA::ALLOCATOR_FLAG_MSAA_TEXTURES_ALWAYS_COMMITTED` off (no MSAA), and allocation callbacks routed to `Zenith_Heap`.

| `Zenith_RHIMemoryClass` | Heap type | D3D12MA flags |
|---|---|---|
| `DEVICE_LOCAL` | `D3D12_HEAP_TYPE_DEFAULT` | none |
| `DEVICE_DEDICATED` | `DEFAULT` | `ALLOCATION_FLAG_COMMITTED` |
| `UPLOAD` | `D3D12_HEAP_TYPE_UPLOAD` (or `GPU_UPLOAD` when `D3D12_FEATURE_D3D12_OPTIONS16::GPUUploadHeapSupported`, the ReBAR case) | none; persistently mapped with `Map(0, nullptr)` |
| `READBACK` | `D3D12_HEAP_TYPE_READBACK` | none; persistently mapped |

- Placement groups are the three heap categories on every tier ([Z2-N-REND-503] table): 1 buffers (`D3D12_HEAP_FLAG_ALLOW_ONLY_BUFFERS`), 2 render-target and depth-stencil textures (`ALLOW_ONLY_RT_DS_TEXTURES`), 3 other textures (`ALLOW_ONLY_NON_RT_DS_TEXTURES`).
- `GetTextureMemoryRequirements` is `ID3D12Device8::GetResourceAllocationInfo2` over the resource desc the create would use; the alignment is 4 KiB (`D3D12_SMALL_RESOURCE_PLACEMENT_ALIGNMENT`) when the texture qualifies (not RT/DS, total size ≤ 64 KiB at the small alignment) and 64 KiB otherwise.
- `CreateHeap` is `D3D12MA::Allocator::AllocateMemory` with `D3D12_RESOURCE_ALLOCATION_INFO{ size, 64 KiB }` and the category's heap flags; placed resources are `D3D12MA::Allocator::CreateAliasingResource1` at the offset ([Z2-N-REND-025], [Z2-N-REND-435]).
- Buffers are created with `D3D12_RESOURCE_FLAG_ALLOW_UNORDERED_ACCESS` when their usage has `STORAGE_WRITE`, textures with `ALLOW_RENDER_TARGET`, `ALLOW_DEPTH_STENCIL` or `ALLOW_UNORDERED_ACCESS` from their usage; initial layouts come from `CreateResource3` (`D3D12_BARRIER_LAYOUT_UNDEFINED` for textures).
- `QueryHeapBudgets` reads `IDXGIAdapter3::QueryVideoMemoryInfo` for `DXGI_MEMORY_SEGMENT_GROUP_LOCAL` and `NON_LOCAL` ([Z2-N-REND-504]); `GetDeviceLocalUsageBytes` is the local segment's `CurrentUsage`.

## Swapchain and presentation

| Element | Rule |
|---|---|
| creation | `IDXGIFactory2::CreateSwapChainForHwnd` on the direct queue with the `HWND` from `Zenith_Window::GetNativeHandle()` (`NATIVE_WINDOW_KIND_WIN32`; a hidden window in CI, `Zenith2/Docs/Design/RHI.md` → "CI windows for GPU tests"), `DXGI_SWAP_EFFECT_FLIP_DISCARD`, buffer count the device's `GetFramesInFlight()` + 1, flags `FRAME_LATENCY_WAITABLE_OBJECT` plus `ALLOW_TEARING` when supported; `MakeWindowAssociation(DXGI_MWA_NO_ALT_ENTER)` (fullscreen is the platform's) |
| formats | SDR `B8G8R8A8_UNORM` buffers with `UNORM_SRGB` RTVs and colour space `RGB_FULL_G22_NONE_P709`; HDR10 `R10G10B10A2_UNORM` with `RGB_FULL_G2084_NONE_P2020`; scRGB `R16G16B16A16_FLOAT` with `RGB_FULL_G10_NONE_P709`, set through `IDXGISwapChain3::SetColorSpace1` after `CheckColorSpaceSupport` ([Z2-N-REND-985]) |
| present modes | FIFO → `Present(1, 0)`; FIFO_RELAXED → `Present(1, 0)` (no DXGI equivalent; reported as FIFO); MAILBOX → `Present(0, 0)` on a flip-model chain with three or more buffers; IMMEDIATE → `Present(0, DXGI_PRESENT_ALLOW_TEARING)` when tearing is supported, else MAILBOX |
| acquire | `GetCurrentBackBufferIndex()`; the back buffers are registered as textures (usage `COLOUR_ATTACHMENT \| TRANSFER_DST \| PRESENT`) at creation and after every resize |
| latency | `SetMaximumFrameLatency(frames in flight)`; `WaitForLatencySlot` waits on `GetFrameLatencyWaitableObject()` |
| pacing hooks | `SetSwapInterval(n)` (1 to 4) becomes the sync interval of every subsequent FIFO `Present(n, 0)`; `SetDesiredPresentTime` returns `FEATURE_UNAVAILABLE` (Recovery.md "Frame pacing hooks") |
| colour-space report | at every creation and resize: `CheckColorSpaceSupport` for the three colour spaces above fills `m_uOutputColourSpacesSupported`; `IDXGISwapChain::GetContainingOutput` → `IDXGIOutput6::GetDesc1` gives `m_bDisplayHdr` (`ColorSpace == DXGI_COLOR_SPACE_RGB_FULL_G2084_NONE_P2020`) and `m_fDisplayMaxLuminanceNits` (`MaxLuminance`) |
| HDR metadata | `SetHDRMetadata` calls `IDXGISwapChain4::SetHDRMetaData(DXGI_HDR_METADATA_TYPE_HDR10, sizeof(DXGI_HDR_METADATA_HDR10), &xHdr10)`, the chromaticities scaled by 50,000 (units of 0.00002), the mastering luminances by 10,000 (units of 0.0001 nits), MaxCLL and MaxFALL in nits, each rounded to the nearest integer |
| timings | `GetFrameStatistics` gives `PresentCount`, `SyncQPCTime`; each maps to a `Zenith_RHIPresentTiming` with the QPC converted to monotonic nanoseconds |
| resize | wait for the direct queue to finish every frame (D3D12 requires every back-buffer reference released first), destroy the back-buffer texture entries at once (a named immediate destruction of entry document "Rules across the API", calling the retirement listener for each: DXGI requires every reference released before `ResizeBuffers`, and the wait just completed every frame that used them), `ResizeBuffers(0, width, height, UNKNOWN, flags)`, re-register; a format or colour-space change recreates the swapchain ([Z2-N-REND-983]) |
| occlusion | `DXGI_STATUS_OCCLUDED` from `Present` counts in `RHI.Swapchain.Occluded` and the next frame presents with `DXGI_PRESENT_TEST` until it returns `S_OK` |

`Present` errors `DXGI_ERROR_DEVICE_REMOVED`, `_RESET` and `_HUNG` move the device to `LOST`.

## Debug layer and validation

| Mode | Setup before device creation |
|---|---|
| `STANDARD` | `D3D12GetDebugInterface(ID3D12Debug6)` → `EnableDebugLayer()` |
| `SYNC` | as `STANDARD` plus `SetEnableSynchronizedCommandQueueValidation(TRUE)` |
| `GPU` | as `SYNC` plus `SetEnableGPUBasedValidation(TRUE)` and `SetGPUBasedValidationFlags(D3D12_GPU_BASED_VALIDATION_FLAGS_NONE)` ([Z2-N-REND-395]) |

After creation, `ID3D12InfoQueue1::RegisterMessageCallback` with `D3D12_MESSAGE_CALLBACK_FLAG_NONE` forwards every message of severity warning, error and corruption to the sink as a `Zenith_RHIValidationMessage` (`m_uMessageID` = the `D3D12_MESSAGE_ID`, `m_szMessageIDName` from the ID-to-name table in `Internal/Windows/Zenith_D3D12MessageNames.inl`); `rhi.validation.breakOnError` additionally sets `SetBreakOnSeverity(ERROR, TRUE)`. WARP supports the debug layer and GPU-based validation, which is what makes the CI requirement of [Z2-N-REND-382] satisfiable headless. Object names use `SetName` with the UTF-16 name.

## Device removal and DRED

Device-creation step 4 on D3D12 (the counterpart of Vulkan's messenger step, `Zenith2/Docs/Design/RHI.md` → "Device creation sequence") acquires the debug interfaces: `ID3D12Debug6` when validation is on and `ID3D12DeviceRemovedExtendedDataSettings1` when breadcrumbs are on; either `D3D12GetDebugInterface` call failing is the step's failure. Development builds (and every build when `rhi.breadcrumbs` is true and the runtime supports it) enable DRED before device creation through `D3D12GetDebugInterface(ID3D12DeviceRemovedExtendedDataSettings1)`: `SetAutoBreadcrumbsEnablement(D3D12_DRED_ENABLEMENT_FORCED_ON)`, `SetPageFaultEnablement(FORCED_ON)`, `SetBreadcrumbContextEnablement(FORCED_ON)`. On loss `CollectDeviceFaultReport` reads `GetDeviceRemovedReason` into `m_acReason` (the HRESULT name), `ID3D12DeviceRemovedExtendedData1::GetAutoBreadcrumbsOutput1` (the last completed and first incomplete operation of each command list, summarised in `m_acFaultDescription` as `<list name>: <op name> #<index>`) and `GetPageFaultAllocationOutput1` (`m_ulFaultAddress` and the allocation's debug name), in addition to Zenith2's own breadcrumbs.

## Timestamps and calibration

`CreateTimestampPool` creates a `D3D12_QUERY_HEAP_TYPE_TIMESTAMP` heap (`COPY_QUEUE_TIMESTAMP` for the copy queue) and a readback buffer of `count × 8` bytes; `ResolveTimestamps` records `ResolveQueryData`; `ReadTimestamps` copies from the mapped readback buffer after the frame completed. `GetTimestampPeriodNs` is `1e9 / GetTimestampFrequency`. `GetClockCalibration` is `GetClockCalibration(&gpu, &cpuQpc)` with the QPC converted to monotonic nanoseconds, `m_bValid` true.

## PIX and RenderDoc capture

- PIX (`rhi.capture=pix`, development builds): before device creation `LoadLibraryW(L"WinPixGpuCapturer.dll")` from the newest `%ProgramFiles%\Microsoft PIX\<version>\` directory (the capturer must load before the first D3D12 call); after creation `DXGIGetDebugInterface1(0, IID_PPV_ARGS(&graphicsAnalysis))` gives `IDXGraphicsAnalysis`, whose `BeginCapture`/`EndCapture` bracket a frame. The library missing: `GetCaptureTool()` is null and `rhi.capture: PIX GPU capturer not found; captures unavailable` is logged.
- RenderDoc (`rhi.capture=renderdoc`): as `Zenith2/Docs/Design/RHI/Vulkan.md → "RenderDoc capture on Vulkan"`, with the device pointer the `ID3D12Device*`.
