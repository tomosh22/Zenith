# ONLINE — tests

## Scope of this file

This file is part of the ONLINE design family; the entry document is `Zenith2/Docs/Design/ONLINE.md`. It lists every test target of ONLINE, every named test with the case it asserts, the fuzz targets, the conformance suite run against every backend's logic, the integration suites, the device and needs-human runs, the stress tests, and which gate step runs each group. Names follow `Zenith2/Docs/Contracts.md` → "Tests and code hygiene gates" (doctest name `"<Library>/<Type>/<Behaviour>"`, ID `Test_<Type>_<Behaviour>`); every ID below is prefixed with an ONLINE type (`Online…`), so it is unique programme-wide (TEST-NAME-UNIQUE).

Common rules:

- No test substitutes a double for a `final` class (FINAL-DOUBLES): sessions are real `Zenith_OnlineSession`s over the real offline backend, the real `Zenith_SaveSystem` over SAVE's in-memory storage (`Zenith2/Engine/ZenithSave/Tests/Support/Zenith_MemorySaveStorage.h`, header-only), PLAT's headless test host (`Zenith2/Docs/Design/PLAT/Platform.md` → "The headless test host") and ONLINE's declared publication port with the header-only recording implementation `Zenith2/Engine/ZenithOnline/Tests/Support/Zenith_OnlineRecordingPort.h` (it records every allocation and park in order and answers `IsReplaying` as the test sets it). The Steam and Play backends' logic runs over their declared seams' scripted recording implementations (`Zenith2/Docs/Design/ONLINE/Backends.md` → "Store backend libraries and what the gates prove").
- Fixtures are generated at test time under `${ZENITH_OUT}/test-fixtures/ONLINE/` by the fixture writer `Zenith2/Engine/ZenithOnline/Tests/Support/Zenith_OnlineFixtures.h` (cooked catalogues built byte by byte from the table of `Zenith2/Docs/Design/ONLINE/Formats.md` → "Cooked online catalogue", envelopes, indexes, manifests, device records, saves written through SAVE), never committed as binaries (orchestrator ruling Q55); runtime tests never link `ZenithAuthoring`. The one committed text fixture pair is the catalogue migration fixture `Zenith2/Tools/Authoring/Tests/Fixtures/Migration/Online/CatalogueDocument/v1.json` and `v1.expected.json`, read only by `ZenithAuthoring_Tests`.
- Every expectation is derivable from this specification by hand (GOLDEN-FILES): byte layouts from the format tables, SHA-256-derived values by comparing with CORE's `Zenith_Sha256Digest` of the specified input (itself proven by CORE's known-answer tests), never a value recorded from a run.
- A test that changes the account checks, at its end, that the test heap reports no leak, that every completion ID the recording port allocated was parked exactly once, and that no file under one account's directories names another account's key (`Zenith_OnlineIsolationChecker`, a helper of the header-only `Tests/Support/Zenith_OnlineIsolationChecker.h`).
