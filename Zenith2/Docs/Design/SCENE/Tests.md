# SCENE design — tests

This file is part of the SCENE design family; the entry document is `Zenith2/Docs/Design/SCENE.md`. It lists every SCENE test with the case it asserts, its file and the gate step that runs it. Test names follow `Zenith2/Docs/Contracts.md` → "Tests and code hygiene gates" (doctest name `"<Library>/<Type>/<Behaviour>"`, ID `Test_<Type>_<Behaviour>`); every test prints the seed of any randomness it uses; none pins a count ([Z2-N-CONTRACT-408]).

The child-process protocol of `Test_HostDocumentStorage_JournalRecoveryOnDisk`, all of it test code in `Zenith_HostDocumentStorage_ChildProcess.cpp`:

1. The parent resolves its own executable path (`GetModuleFileNameW(nullptr, …)` on Windows, `readlink("/proc/self/exe")` on Linux) and launches it with the arguments `--test-case=ZenithDocumentHost/HostDocumentStorage/CrashChild --no-skip` and the environment `ZENITH2_CHILD_ROOT=<temporary root>`, `ZENITH2_CHILD_CRASH_AFTER=<N>`, `ZENITH2_CHILD_TORN=<0|1>` (`CreateProcessW` / `posix_spawn`), then waits for it.
2. The child's test case reads the three variables, creates a host storage on the root, wraps it in the test-only decorator `Zenith_CrashingDocumentStorage` (forwarding every member; before the mutation with index N it either calls `std::_Exit(77)` or, with torn set and the mutation a `WriteFlushed`, forwards the first half of the bytes and then calls `std::_Exit(77)`), and runs the same 5-document `ApplyPlan` as the in-memory test; completing the batch returns normally (exit code 0).
3. Any other exit code, or a child that runs longer than 60 seconds (the parent then kills it), fails the parent with the child's exit code and N in the message.
