# GAME design — tests

This file is part of the GAME design family; the entry document is `Zenith2/Docs/Design/GAME.md`. It lists every GAME test by file, target and assertion. All tests are doctest cases registered with CTest, one CTest per case ([Z2-N-ARCH-179]), pass/fail only, with no pinned count (`Zenith2/Docs/Contracts.md` → "Tests and code hygiene gates"), and land in the same ticket as the code they test. Every test-case name is unique programme-wide (the TEST-NAME-UNIQUE ruling): no GAME case shares a name with another area's case, and a suite of one stage never re-declares a case of another. No test double replaces a concrete class or a type without a seam (the FINAL-DOUBLES ruling): a test that needs a world uses a real `Zenith_WorldSimulation` on the Custom backend (and on Flecs and EnTT where the test is instantiated per backend), a real `Zenith_TypeRegistry`, a real `Zenith_StringTable` and the real `Zenith_MemoryGovernor` configured through its keys; seams are the interfaces GAME owns or consumes (`Zenith_CollisionQuery`, `Zenith_LifecycleListener`, `Zenith_AsyncPublicationHandler`), the runtime's test hooks (`Zenith_RuntimeTestHooks`, GA5 (h)) and the header-only probe module `Zenith2/Engine/ZenithRuntime/Tests/Support/Zenith_LifecycleProbe.h` (non-Core `Tests/Support/` is headers only and compiled by no target, [Z2-N-ARCH-255], the X184 ruling). No GAME test needs a GPU except the Stage 7 XR case `Test_XRGameplay_DirectorDrivesStereoPair` (an OpenXR runtime on the GPU, skipped with exit code 77 without one); everywhere else the camera's render-side effect is a property write the tests read back.

Golden and fixture files follow the GOLDEN-FILES ruling: every expected output GAME's tests compare against is derivable from this specification and is a committed text file edited by hand (the binding declarations golden, the input scripts of the scenarios and of `PlaythroughS01`); scenes and assets the suites need are text sources cooked at test time; nothing GAME's tests read is a recorded run.
