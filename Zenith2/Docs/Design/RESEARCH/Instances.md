# RESEARCH design: decisions as instances of the methodology

This file is part of the RESEARCH design family; the entry document is `Zenith2/Docs/Design/RESEARCH.md`. Every measured or ruled decision in Zenith2 is an instance of the one methodology of `Zenith2/Docs/Design/RESEARCH/Methodology.md`. This file names each instance, its profile, its harness, run and ruling tickets, its study path and the operator form of its acceptance rule. It does not re-specify any harness: each harness is specified by its owning area's design, cited in the last column. The check `Pwsh_Research_CheckInstanceMap` keeps the first table complete against `Zenith2/Docs/DecisionLog.md` → "Open decisions".

## Scope of this file

- Ticket IDs are draft IDs (`Z2T-<AREA>-NNN`) as drafted; the filer maps them to board keys.
- A study path is `Zenith2/Docs/Research/<Study>/`; where an area's design or ticket names another path for the same data, the canonical layout of `Zenith2/Docs/Design/RESEARCH/Formats.md` → "Research tree layout" applies and cross-area row RS1 asks the area to conform.
- The rule column documents the translation the harness ticket writes into `study.json`, written in the operators but not always as one parsed expression; the parsed rule is the study's, and `Pwsh_Research_CheckInstanceMap` checks only that every open decision has its row. The open decision's own text in `Zenith2/Docs/DecisionLog.md` stays the authority, and "Instance phrase mapping" of the methodology fixes every phrase used.
- "Incumbent" names the alternative a false rule keeps; a decision with no default between its candidates has none, and its false-outcome is `human(…)` or `blocked(…)` (`Zenith2/Docs/Design/RESEARCH/Methodology.md` → "Hypothesis and acceptance rule").

## Instance obligations

What each owning area's A5 revision applies (cross-area row RS1):

- Every decision ticket above carries the template lines of `Zenith2/Docs/Design/RESEARCH/Formats.md` → "Decision ticket template" with the profile of its row, and the two DoD lines.
- Every harness ticket of an RA, RS, RJ, RB or RP row commits `Zenith2/Docs/Research/<Study>/study.json` for its study, in the same diff as the harness, with cells, metrics and selectors matching its harness's output schema, and `Pwsh_Research_StudyFilesValid` passing.
- Every ruling ticket's outputs move to the canonical layout: `runs/<RunId>/` for raw data (the harness reports become `raw/` files), `Reports/<Z2-D-NNN>.md` for the report.
- A harness whose output already carries per-repetition values (`samplesNs`, `repetitionMeansNs`) keeps them; the selectors read them, and no harness changes its measurement for this methodology.
